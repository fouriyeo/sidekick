## D1 · 命名：Sidekick（2026-10-31）｜已被 D114 更新

- 决策：英文名 Sidekick、仓库 `sidekick`；中文「小跟班」原为产品名，D114 起只作手机宠物角色名。
- 原因：直白、一听就懂、带宠物感；放弃 Familiar/使魔、Tether、信鸽。

## D2 · 手机端必须是独立 App（2026-10-31）｜生效

- 决策：手机做真正的安卓 App（Tauri 安卓目标），网页只作下载入口与调试预览。
- 原因：用户要求「用的不是浏览器，是软件」；长期常驻宠物 App 需要应用身份、后台与后续 BLE 能力。

## D3 · 技术栈：Tauri 2 双端（2026-10-31）｜生效

- 决策：桌面与手机都用 Tauri 2（Rust 核心 + Web 前端），单仓库共前端与协议。
- 放弃：Flutter（用户选 Tauri，工具链也卡过）、React Native、原生 Kotlin、Electron、纯 Node 守护进程。
- 代价：移动端蓝牙生态弱、Android 工具链重；收益：Rust 掌控网络/传输，Web UI 迭代快。

## D4 · 通信：局域网 WebSocket 优先，蓝牙延后（2026-10-31）｜生效

- 决策：MVP 走局域网 WebSocket（端口后由 D38 改为 47810 候选）；蓝牙只作后续传输方案。
- 原因：最快验证「手机 ↔ 电脑」闭环；蓝牙预研可行但工程量大（`docs/ble-notes.md`），传输层可替换。

## D5 · 角色：电脑服务端、手机客户端（2026-10-31）｜生效

- 决策：电脑起 HTTP/WS 服务，手机 App 主动发现并连接（D37/D45）。
- 原因：电脑网络与常驻能力更稳；手机端库生态成熟，iOS 后台更友好。

## D6 · 手机用 Rust 建连，而非 WebView WebSocket（2026-10-31）｜生效

- 决策：前端经 Tauri 命令/事件调 Rust 的 tokio-tungstenite 客户端。
- 原因：规避 Android WebView 对 `ws://` 混合内容的限制；为换蓝牙传输留统一接口。

## D7 · 单仓库 + `app/` 目录（2026-10-31）｜生效

- 决策：Tauri 项目统一放 `app/`，协议 `protocol/`、文档 `docs/`。
- 原因：桌面与手机共前端与协议，单仓库降低同步成本。

## D8 · 协议 v0：广播式 chat/system，无鉴权（2026-10-31）｜生效

- 决策：WS JSON 文本帧、服务端广播；v0 只有 `chat` / `system` 两类消息。
- 代价：同网段任何人可连；配对与鉴权仍未实现（P1）。

- 重启前先定：Tauri 插件还是 Python sidecar（见 `docs/ble-notes.md`）。

## D45 · 断连自动重连：指数退避 + 静默重新发现（2026-11-01）｜生效

- 决策：断连/启动未连上/手动失败进入重连循环，每次先静默 UDP 重新发现，发现不到退回上次地址；退避 1→2→4→8→16→30s（封顶 30s），手动连接/重新搜索清零，切后台暂停、回前台立即重试。
- 放弃：手机 Rust 原生重连（要重做发现与 UI 协调）、WS 心跳（半开连接仍靠 TCP 发现）。
- 代价：电脑恢复最多等一个退避周期；无心跳时睡眠/静默丢包可能长时间显示「已连接」。
