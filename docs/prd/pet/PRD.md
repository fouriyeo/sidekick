# PRD：小跟班 · 情绪宠物

**版本** v0.1 · **日期** 2026-10-31 · **状态** 草稿（待评审）
**平台** 手机横屏（Android 优先）；桌面端不渲染宠物
**关联** [SPEC](./SPEC.md) · [ACCEPTANCE](./ACCEPTANCE.md) · [产品原则](../../product/principles.md) · [交互规范](../../standards/ux.md)

## 0. 一页摘要

一只住在横屏手机里的黏土小宠物，会想你、听你说话、等你回来。本期只做**纯陪伴**：让用户愿意把手机横放在桌边，偶尔摸一下、看一眼，而不是被任务和通知追着跑。

- **P0**：命名、桌面陪伴、摸摸/戳一戳、情绪与记忆、横屏双姿态、麦克风联动、设置。
- **不做**：饥饿/签到/排行榜、AI 状态看板、桌面宠物、竖屏布局、跨端响应式。
- **成功**：用户愿意持续打开、主动互动，并用“治愈/可爱/想摸”描述它。

## 1. 背景与目标

### 1.1 背景

- AI 工具让工作更快，但桌面工作变得更安静、更机械：屏幕上是任务、终端、diff，手机只是通知屏。
- Sidekick 的差异化不是再做一个控制台，而是让手机变成一个“活着的小家伙”。它是产品的情感入口，也是后续 AI 状态、通知、麦克风功能的载体。
- 前端重构脚手架已就绪，宠物是下一个核心界面；先做纯陪伴，验证“用户愿意把它放在桌上”，再接工作状态。
- 不做会怎样：产品仍是聊天壳，缺少记忆点；做了会怎样：建立情感连接，让麦克风等效率功能也有温度。

### 1.2 目标用户

| 用户角色 | 特征 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| AI 结对开发者 | macOS、长时间与 AI 结对、手机放支架 | 低打扰陪伴；工作间隙放松 10 秒 | 写需求、改 bug 的间隙 |
| 内容创作者/研究者 | 长时间写文档、不喜欢通知轰炸 | 安静的陪伴感；一个会回应的桌面小物 | 写作、查资料、思考时 |
| 桌搭爱好者 | 在意桌面视觉、愿意摆放手机 | 好看、想摸、有生命感 | 手机横放当桌边摆件 |

非目标：需要生产力仪表盘的用户、儿童、公共网络用户、竖屏用户。详见 [product/users.md](../../product/users.md)。

### 1.3 目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
| --- | --- | --- | --- |
| 用户愿意持续打开 | 7 日回访率 | ≥ 40% `[假设]` | 本地事件 + 试用记录 |
| 宠物互动成为自然动作 | 单次打开有效互动率；周均互动次数 | ≥ 60%；≥ 5 次 `[假设]` | `pet_interact` |
| 情绪价值可感知 | 5 人试用中正面描述人数 | ≥ 4/5 `[假设]` | 试用访谈 |
| 不打扰 | 气泡主动关闭率 | < 20% `[假设]` | `pet_bubble` |
| 体验流畅 | 真机帧率；触摸反馈延迟 | 60fps；≤ 100ms | 真机测量 |

指标口径与隐私规则见 [product/metrics.md](../../product/metrics.md)。所有目标值是假设，试用后校准。

## 2. 需求概述

让手机横屏变成一个会呼吸、会回应、会想你的小宠物。

**P0 模块（4 个）**

| 模块 | 包含 |
| --- | --- |
| 初次见面与陪伴 | 3.1 命名 + 3.2 桌面陪伴 |
| 触摸互动 | 3.3 |
| 情绪与记忆 | 3.4 + 3.5 麦克风联动 |
| 横屏体验 | 3.6 双姿态 + 3.7 设置 |

## 3. 功能详细设计

### 3.1 首次见面与命名（P0）

**功能描述**：第一次打开宠物页，宠物从睡梦中醒来，邀请用户给它起名；可以跳过，默认叫“小跟班”。

**用户故事**：作为第一次使用的用户，我希望给宠物起一个名字，以便它对我而言不是一只通用动画。

**业务规则**

1. 首次进入宠物页时触发；不依赖电脑连接，离线可用。
2. 名字长度 1–8 个字符；去除首尾空格；不允许换行、URL、纯空白。
3. 提供默认名“小跟班”和“先这样叫我”跳过入口。
4. 名字只在本机保存；设置页可改名，改名后下一次气泡使用新名字。
5. 命名流程不请求麦克风、通知、定位等任何权限。
6. 宠物名字不写入任何统计事件，只记录 `source: default/custom`。

**交互流程**：进入 → 宠物醒来、伸懒腰 → 出现名字输入 → 确认/跳过 → 宠物叫一声/点头 → 进入陪伴。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 输入为空 | 禁用确认，保留默认名 | “叫小跟班也可以。” |
| 超长/含换行 | 截断到 8 字符并提示 | “名字短一点，它记得住。” |
| 本地保存失败 | 本次会话使用默认名，不阻塞 | “名字这次先不保存，下次再试。” |

### 3.2 桌面陪伴与时间感（P0）

**功能描述**：宠物在无操作时自己生活：呼吸、眨眼、张望、伸懒腰、打哈欠、夜间睡觉；用户回来时轻轻打招呼。

**用户故事**：作为长时间工作的用户，我希望桌边有个会自己动的小生命，以便工作间隙看一眼就能放松。

**业务规则**

1. 待机动画池：呼吸、眨眼、张望、甩尾、伸懒腰、舔毛；随机间隔 4–12 秒，避免固定循环。
2. 时段：06:00–11:00 早晨（伸懒腰多）；11:00–18:00 白天（常态）；18:00–23:00 傍晚（更安静）；23:00–06:00 夜间（困倦/睡觉）。
3. 夜间连续 5 分钟无互动 → 入睡；任意触摸唤醒；不弹通知、不主动出声。
4. 离开超过 6 小时再回来 → 3 秒“想你”问候；超过 3 天 → 特殊问候，但文案不出现“你怎么才回来”。
5. 气泡最多 1 条/30 秒，自动消失 4 秒；录音/转写期间不出气泡。
6. App 进入后台立即暂停动画与计时；回前台先眨眼一次再恢复。
7. 支架模式下，充电且前台时可保持屏幕常亮（设置默认开，可关）；非充电不默认常亮。
8. 宠物不主动发系统通知、不产生红点、不展示未读数。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 系统时间/时区变化 | 重新计算时段；不补发问候、不奖励“时间旅行” | 无 |
| 长时间后台被系统杀死 | 重新启动后从本地恢复；不重复问候 | 无 |
| 低电量模式 | 降低 idle 频率，保留触摸反馈 | 无 |
| 屏幕常亮导致发热 | 2 分钟无操作自动暗到 70% | 触摸恢复亮度 |

### 3.3 触摸互动（P0）

**功能描述**：用户摸摸或戳一戳宠物，宠物给出即时、温柔、有性格的反应。

**用户故事**：作为桌边用户，我希望伸手摸一下就有回应，以便获得即时的情绪反馈。

**业务规则**

1. 热区：宠物舞台整体 + 24dp 外扩；不要求精确点到宠物身体。
2. 摸摸：1.5 秒内至少 2 次方向变化；宠物靠近、闭眼、轻震；持续 3 秒进入开心并出现最多 6 个爱心。
3. 戳一戳：点按 <250ms；宠物看向手指、好奇；2 秒内 3 次快速戳 → 扭头 3 秒，之后恢复，不记仇。
4. 互动冷却 2 秒；冷却期间仍有轻反馈，但不重复触发大动画。
5. 多指触摸只认第一根手指；录音/转写期间禁用宠物互动，麦克风优先。
6. 不支持拖拽、捏合、画圈等复杂手势（P0）。
7. 任何互动不改变系统音量、不弹通知、不发送网络请求。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 动画加载失败 | 静态形象 + CSS 呼吸；轻震/气泡仍可用 | 无（静默降级） |
| 连续快速点击 | 只触发一次好奇，其余忽略 | 无 |
| 录音中触摸宠物 | 不响应；麦克风按钮优先 | 无 |

### 3.4 情绪、精力与记忆（P0）

**功能描述**：宠物有隐藏的心情、精力和亲密度；会记住名字、上次见面和互动习惯，但从不显示数值、不惩罚用户。

**用户故事**：作为用户，我希望它记得我、有连续的情绪，以便它像一个真实的陪伴者，而不是随机动画。

**业务规则**

1. 心情状态：安静（content）、开心（happy）、好奇（curious）、困倦（sleepy）、倾听（listening）、得意（proud）、关心（concerned）；由互动、时间和麦克风状态驱动。
2. 精力 0–100，隐藏：前台每 30 分钟 -1，后台每 2 小时 -1；睡眠每小时 +5；只影响 idle 频率和哈欠，不影响可用性。
3. 亲密度 0–100，隐藏：每次有效互动 +1，每天最多 +5；影响问候多样性和 idle 变化，不显示等级。
4. 负面状态最多持续 3 秒；不跨会话记仇；没有饥饿、死亡、掉级。
5. 保存字段：名字、心情、精力、亲密度、上次见面时间、设置；不保存聊天、音频、转写。
6. 每次变化后保存；App 进入后台再保存一次；启动时恢复；保存带版本号。
7. 用户可在设置中重置宠物：二次确认；重置名字、心情、精力、亲密度、上次见面；不可撤销。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 存档损坏/版本不兼容 | 回退默认值，尽量保留名字 | “它有点睡迷糊了，先从头认识你。” |
| 存储空间不足 | 本次会话不保存，继续可用 | “这次记不住，下次再试。” |
| 用户修改系统时间 | 只重算时段，不发放奖励 | 无 |
| 重置时误触 | 二次确认 + 明确“不可撤销” | “确定要让它重新认识你吗？” |

### 3.5 与麦克风联动（P0）

**功能描述**：用户使用外设麦克风时，宠物用表情和动作回应：倾听、得意、关心；但不显示转写内容、不干扰录音。

**用户故事**：作为用户，我希望说话时宠物在听、完成后为我高兴，以便工具操作也有陪伴感。

**业务规则**

1. 开始录音：若在睡觉则轻轻醒来；竖耳、看向用户；不出气泡。
2. 倾听中：轻微呼吸/摆动，停止随机 idle；不遮挡波形、计时、取消区。
3. 转写成功：2 秒得意/开心 + 少量闪光；可出一句“收到。”；不显示转写全文。
4. 取消：眨眼后回到之前心情；不出气泡、不表达失望。
5. 失败：歪头/耳朵下垂 1.5 秒；可说“没听清，再来一次？”；不责怪用户。
6. 麦克风状态优先于心情；录音结束后恢复录音前的心情，除非成功/失败触发了短暂情绪。
7. 宠物渲染失败不影响麦克风；麦克风失败也不改变宠物长期心情。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 录音权限被拒 | 宠物回到 idle；不追问 | 麦克风模块负责提示 |
| 连接中断 | 宠物不表现“被抛弃”；回到 idle | 麦克风模块提示重连 |
| 转写超时 | 关心 1.5 秒后恢复 | 麦克风模块给“再说一次” |

### 3.6 横屏双姿态（P0）

**功能描述**：同一横屏界面支持支架放置和手持使用；布局、按钮大小、界面元素密度随姿态变化。

**用户故事**：作为用户，我希望手机放在支架上时像桌宠，拿起来时像麦克风手柄，以便两种场景都顺手。

**业务规则**

1. 两种姿态：支架（docked）、手持（handheld）；默认自动判断，也允许手动锁定。
2. 自动判断：充电中 + 静止 10 秒 → 支架；检测到拿起/移动 → 手持；不确定时保持上一次。
3. 支架：宠物更大、居中偏右；界面元素 5 秒无操作自动隐藏；麦克风为底部居中胶囊（高 72dp）；充电时默认屏幕常亮。
4. 手持：宠物位于上 2/3；右下圆形麦克风（直径 96dp）；左下取消；界面元素常显；触控目标 ≥64dp。
5. 姿态切换动画 320ms；宠物与按钮不重叠、不跳位；录音过程中不切换布局。
6. 手动选择优先于自动，并持久化；设置里可恢复自动。
7. 竖屏不提供完整布局，只显示“请横屏使用”的提示；横屏恢复后回到之前状态。
8. 所有控件避开刘海、挖孔、圆角、手势条安全区。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 自动判断反复跳变 | 锁定上次模式 30 秒，等待稳定 | 无 |
| 录音中拿起手机 | 保持当前布局，录音结束后再切 | 无 |
| 竖屏时正在录音 | 停止录音并丢弃，提示横屏后再试 | “横屏后再说一次。” |
| 安全区变化（旋转/分屏） | 重新布局，不遮挡控件 | 无 |

### 3.7 设置与关于（P0）

**功能描述**：用户可改名、开关震动/声音、减少动效、锁定姿态、屏幕常亮、重置宠物、查看隐私说明。

**业务规则**

1. 设置入口：舞台角落一个可见的设置图标，一次点击进入；不藏在长按菜单。
2. 默认值：震动开、声音关、减少动效跟随系统、姿态自动、屏幕常亮仅充电时开。
3. 改名规则同 3.1；保存后立即生效。
4. 重置需二次确认，明确不可撤销。
5. 关于页说明：宠物数据仅存本机、卸载会丢失、无账号/云同步；版本号；开源许可证入口（后续）。
6. 设置页不请求网络、不请求权限。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 保存失败 | 保留原值，提示重试 | “没保存上，再试一次。” |
| 重置中退出 | 不执行重置，保持原状 | 无 |

### 3.8 P1 / P2（本期不实现）

- **P1 喂零食/收藏**：拖星星给宠物；不做库存、饥饿、每日任务；先验证纯陪伴是否成立。
- **P1 更多互动**：躲猫猫、跟随手指、节日问候；不引入任务系统。
- **P2 AI 状态映射**：working/waiting/error 以克制的动作表达；不得把宠物变成仪表盘；需单独 PRD。
- **P2 桌面宠物**：不在本期；桌面端只做麦克风状态。

## 4. 非功能需求

| 类别 | 要求 | 验收标准 |
| --- | --- | --- |
| 性能 | 真机动画流畅 | 60fps；单帧主线程 <16ms；长任务 <50ms |
| 响应 | 触摸/按钮反馈快 | ≤100ms 有可见反馈 |
| 加载 | 宠物页进入后可互动 | ≤1.5s；资源懒加载 |
| 内存 | 中端安卓稳定 | 宠物页常驻 ≤150MB `[待基线]` |
| 电量 | 支架模式可长时间放置 | 30 分钟掉电 ≤5% `[待基线]`；低电量降频 |
| 隐私 | 宠物不联网、不录音 | 无网络请求；不请求麦克风/通知权限 |
| 持久化 | 重启不丢关键状态 | 名字/心情/设置恢复；损坏可回退 |
| 兼容性 | Realme RMX3370 / Android 13 横屏 | 16:9、20:9 不遮挡、不滚动 |
| 无障碍 | 可感知、可操作 | 标签、对比度、减少动效、非颜色单一提示 |
| 可靠性 | 降级可用 | 动画失败有静态替代；存储失败不阻塞 |

## 5. 数据需求

事件口径与隐私规则见 [product/metrics.md](../../product/metrics.md)。本功能事件：

| 事件 | 触发 | 关键属性 | 用途 |
| --- | --- | --- | --- |
| `pet_open` | 宠物页进入前台 | `posture`, `mood`, `energy_bucket` | 使用频率、姿态 |
| `pet_name_set` | 命名/改名 | `source`（default/custom），不记名字 | 命名完成率 |
| `pet_interact` | 摸摸/戳结束 | `kind`, `duration_bucket`, `mood_before`, `mood_after` | 互动偏好 |
| `pet_bubble` | 气泡展示/关闭 | `trigger`, `copy_id`, `dismissed` | 打扰度 |
| `pet_posture` | 姿态切换 | `from`, `to`, `auto` | 自动判断准确率 |
| `pet_mic_react` | 麦克风引发反应 | `state` | 联动自然度 |
| `pet_reset` | 重置 | 无 | 重置使用 |

不记录：宠物名字、聊天、音频、转写、目标应用、剪贴板。事件仅存本机，默认保留 30 天，可清除。

## 6. 验收标准（核心）

| 编号 | 场景 | Given | When | Then |
| --- | --- | --- | --- | --- |
| PET-AC-01 | 首次命名 | 首次进入宠物页 | 输入名字并确认 | 宠物使用新名字；重启后保留 |
| PET-AC-02 | 跳过命名 | 首次进入 | 点“先这样叫我” | 使用默认名“小跟班”，进入陪伴 |
| PET-AC-03 | 待机动画 | 宠物页前台 30 秒无操作 | 观察 | 出现呼吸/眨眼/张望等随机动作，无固定短循环 |
| PET-AC-04 | 摸摸 | 宠物 idle | 在宠物区域来回滑动 3 秒 | 宠物靠近/闭眼，出现开心与轻震 |
| PET-AC-05 | 戳一戳 | 宠物 idle | 点按宠物 1 次 | 宠物看向手指，好奇反应 |
| PET-AC-06 | 快速连戳 | 宠物 idle | 2 秒内戳 3 次 | 扭头 3 秒后恢复，不记仇 |
| PET-AC-07 | 回来问候 | 离开 6 小时后回前台 | 进入宠物页 | 3 秒“想你”问候，不出现愧疚文案 |
| PET-AC-08 | 夜间睡觉 | 23:00 后 5 分钟无互动 | 观察 | 入睡；触摸唤醒；不弹通知 |
| PET-AC-09 | 姿态切换 | 支架模式 | 拿起点亮手持 | 布局 320ms 内切换；录音中不切 |
| PET-AC-10 | 麦克风联动 | 麦克风开始录音 | 观察宠物 | 竖耳倾听；不遮挡波形/计时/取消 |

完整用例见 [ACCEPTANCE.md](./ACCEPTANCE.md)。

## 8. 风险与依赖

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 美术资产难产/风格不统一 | 高 | 阻塞 P0 | 先做剪影和 3 个表情验证，再扩动作 |
| 中端安卓掉帧 | 中 | 体验差 | 限制网格/粒子；真机 60fps 门禁；降级静态 |
| OLED 烧屏 | 中 | 硬件损伤 | 2 分钟自动暗屏；轻微呼吸位移 |
| 卸载丢宠物引发负面情绪 | 中 | 情感伤害 | 关于页说明；P1 考虑导出/备份 |
| 范围膨胀（喂食/游戏/服装） | 高 | 延期 | P1/P2 清单；P0 模块 ≤5 |
| 用户期待 AI 状态映射 | 中 | 预期落差 | PRD/关于页明确本期纯陪伴 |
| 姿态自动判断不准 | 中 | 来回跳 | 不确定保持上次；手动锁定 |
| 与麦克风互相遮挡 | 中 | 操作失败 | 跨功能契约；录音时禁用宠物互动 |

## 9. 开放问题

- 默认名是否用“小跟班”，还是让用户必须起名？
- 声音默认关是否足够？是否提供“只在支架模式开”？
- 支架模式屏幕常亮默认开，还是只在充电时开？
- 宠物状态是否提供导出/备份？卸载丢失如何告知？
- AI 状态映射的优先级和表达边界，何时做？
- 美术资产来源（自绘/AI 辅助/外包）与 Rive 编辑器许可。
- 是否需要“睡眠时间”跟随用户作息，而不是固定 23:00。
