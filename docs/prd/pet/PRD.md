# PRD：小跟班 · 情绪宠物

**版本** v0.3 · **日期** 2026-11-04 · **状态** 草稿（AI 联动作为独立 P1 先做；触摸互动已下线 D69）
**平台** 手机端（Android 优先；只支持竖屏）；桌面端不渲染宠物
**关联** [SPEC](./SPEC.md) · [ACCEPTANCE](./ACCEPTANCE.md) · [产品原则](../../product/principles.md) · [交互规范](../../standards/ux.md)

## 0. 一页摘要

一只住在手机里的黏土小宠物，会想你、听你说话、等你回来。本期只做**纯陪伴**：让用户愿意把手机放在桌边，偶尔看一眼，而不是被任务和通知追着跑。

- **P0**：命名、桌面陪伴、情绪与记忆、单竖屏布局、设置；麦克风联动为下一阶段。
- **不做**：触摸互动（点击/抚摸宠物无任何反应，D69）、饥饿/签到/排行榜、AI 状态看板、桌面宠物、横屏/平板布局、跨端响应式。
- **成功**：用户愿意持续打开，并用“治愈/可爱/想放在桌边”描述它。

## 1. 背景与目标

### 1.1 背景

- AI 工具让工作更快，但桌面工作变得更安静、更机械：屏幕上是任务、终端、diff，手机只是通知屏。
- Sidekick 的差异化不是再做一个控制台，而是让手机变成一个“活着的小家伙”。它是产品的情感入口，也是后续 AI 状态、通知、麦克风功能的载体。
- 前端重构脚手架已就绪，宠物是下一个核心界面；先做纯陪伴，验证“用户愿意把它放在桌上”，再接工作状态。
- 不做会怎样：产品仍是聊天壳，缺少记忆点；做了会怎样：建立情感连接，让麦克风等效率功能也有温度。

### 1.2 目标用户

| 用户角色 | 特征 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| AI 结对开发者 | macOS、长时间与 AI 结对、手机放支架 | 低打扰陪伴；工作间隙放松 10 秒 | 写需求、改 bug 的间隙 |
| 内容创作者/研究者 | 长时间写文档、不喜欢通知轰炸 | 安静的陪伴感；一个会回应的桌面小物 | 写作、查资料、思考时 |
| 桌搭爱好者 | 在意桌面视觉、愿意摆放手机 | 好看、有生命感、不打扰 | 手机竖放当桌边摆件 |

非目标：需要生产力仪表盘的用户、儿童、公共网络用户、需要专门竖屏布局的用户。详见 [product/users.md](../../product/users.md)。

### 1.3 目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
| --- | --- | --- | --- |
| 用户愿意持续打开 | 7 日回访率 | ≥ 40% `[假设]` | 本地事件 + 试用记录 |
| 情绪价值可感知 | 5 人试用中正面描述人数 | ≥ 4/5 `[假设]` | 试用访谈 |
| 不打扰 | 气泡主动关闭率 | < 20% `[假设]` | `pet_bubble` |
| 体验流畅 | 真机帧率；按钮反馈延迟 | 60fps；≤ 100ms | 真机测量 |

指标口径与隐私规则见 [product/metrics.md](../../product/metrics.md)。所有目标值是假设，试用后校准。

## 2. 需求概述

让手机变成一个会呼吸、会回应、会想你的小宠物。

**P0 模块（3 个）**

| 模块 | 包含 |
| --- | --- |
| 初次见面与陪伴 | 3.1 命名 + 3.2 桌面陪伴 |
| 情绪与记忆 | 3.4（3.5 麦克风联动为 P1 契约） |
| 手机体验 | 3.6 单竖屏布局 + 3.7 设置 |

## 3. 功能详细设计

### 3.1 首次见面与命名（P0）

**功能描述**：第一次打开宠物页，宠物从睡梦中醒来，邀请用户给它起名；可以跳过，默认叫“小跟班”。

**用户故事**：作为第一次使用的用户，我希望给宠物起一个名字，以便它对我而言不是一只通用动画。

**业务规则**

1. 首次 = 无存档或存档 `onboarded=false`；不依赖电脑连接，离线可用；跳过即写默认名 + `onboarded=true`，保存失败不置位、不阻塞。
2. 名字长度 1–8 个字符；去除首尾空格；不允许换行、URL、纯空白。
3. 提供默认名“小跟班”和“先这样叫我”跳过入口。
4. 名字只在本机保存；设置页可改名，改名后下一次气泡使用新名字。
5. 命名流程不请求麦克风、通知、定位等任何权限。
6. 宠物名字不写入任何统计事件，只记录 `source: default/custom`。
7. 重置宠物清除宠物数据（含 `onboarded`），保留设置，下次进入重新走命名。

**交互流程**：进入 → 宠物醒来、伸懒腰 → 出现名字输入 → 确认/跳过 → 宠物叫一声/点头 → 进入陪伴。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 输入为空 | 禁用确认，保留默认名 | “叫小跟班也可以。” |
| 超长/含换行 | 截断到 8 字符并提示 | “名字短一点，它记得住。” |
| 本地保存失败 | 本次会话使用默认名，不置位 `onboarded`，不阻塞 | “名字这次先不保存，下次再试。” |

### 3.2 桌面陪伴与时间感（P0）

**功能描述**：宠物在无操作时自己生活：呼吸、眨眼、张望、伸懒腰、打哈欠、夜间睡觉；用户回来时轻轻打招呼。

**用户故事**：作为长时间工作的用户，我希望桌边有个会自己动的小生命，以便工作间隙看一眼就能放松。

**业务规则**

1. 待机动画池：呼吸、眨眼、张望、甩尾、伸懒腰、舔毛；随机间隔 4–12 秒，避免固定循环。
2. 时段：06:00–11:00 早晨（伸懒腰多）；11:00–18:00 白天（常态）；18:00–23:00 傍晚（更安静）；23:00–06:00 夜间（困倦/睡觉）。
3. 夜间（23:00–06:00）前台连续 5 分钟无互动 → 入睡；06:00 后自动醒（回前台按跨夜规则重算）；不弹通知、不主动出声。点击/抚摸宠物不会唤醒。
4. 离开 >6 小时回来 → 3 秒“想你”问候；>3 天 → 特殊问候，但文案不出现“你怎么才回来”；与睡眠冲突时睡眠优先。
5. 气泡最多 1 条/30 秒，自动消失 4 秒；录音/转写期间不出气泡（P1）。
6. App 进入后台暂停动画与计时；设置/聊天覆盖层不卸载宠物，暂停 idle/睡眠计时并保留心情；回前台先眨眼一次再恢复。
7. 后台跨夜离开 ≥5 分钟回前台直接 sleeping，不弹问候。宠物页前台默认屏幕常亮（支架放置不被系统锁屏打断，默认最长 2 小时可调），设置页可关闭；聊天页与后台交给系统默认熄屏。
8. 宠物不主动发系统通知、不产生红点、不展示未读数。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 系统时间/时区变化 | 重新计算时段；不补发问候、不奖励“时间旅行” | 无 |
| 长时间后台被系统杀死 | 重新启动后从本地恢复；不重复问候 | 无 |
| 低电量模式 | 降低 idle 频率，保留 AI/麦克风反馈 | 无 |
| 系统锁屏（屏幕常亮已关闭/最长常亮到点/系统强制锁屏） | 锁屏即暂停；解锁回前台恢复；常亮默认开、最长默认 2 小时，关闭或到点后按系统策略 | 无 |

### 3.3 触摸互动（非目标，D69）

当前阶段不实现宠物触摸互动：点击、长按、来回抚摸宠物都不产生任何反应（无气泡/震动/爱心/姿态切换），也不写存档。相应手势阈值、冷却、亲密度与设置页无障碍替代按钮均已下线；后续如需恢复，应作为独立功能重新评审。

### 3.4 情绪、精力与记忆（P0）

**功能描述**：宠物有隐藏的心情和精力；会记住名字和上次见面，但从不显示数值、不惩罚用户。

**用户故事**：作为用户，我希望它记得我、有连续的情绪，以便它像一个真实的陪伴者，而不是随机动画。

**业务规则**

1. 心情状态：content/happy/curious/sleepy/listening/proud/concerned；存档只存基线心情（content/sleepy），其余瞬态不落盘；启动按时段/精力重算基线。happy 来自命名完成，curious 来自首次见面。
2. 精力初值 100、clamp 0–100，隐藏：前台每 30 分钟 -1、后台每 2 小时 -1、睡眠每小时 +5；`[假设]` energy<30 哈欠增多、<15 sleepy；只影响 idle/哈欠，不影响可用性。
3. 负面状态最多持续 3 秒；不跨会话记仇；没有饥饿、死亡、掉级。
4. 保存字段：名字、基线心情、精力、`onboarded`、`lastSeenAt/lastInteractionAt/lastEnergyAt`、设置；不保存聊天、音频、转写。`lastInteractionAt` 由命名、麦克风事件、覆盖层关闭更新。
5. 存档走 plugin-store（500ms 防抖，后台立即写）；启动恢复并迁移，损坏回退默认。
6. 重置宠物：二次确认；清宠物数据（含 `onboarded`）、保留设置；不可撤销，重新走命名。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 存档损坏/版本不兼容 | 回退默认值，尽量保留名字 | “它有点睡迷糊了，先从头认识你。” |
| 存储空间不足 | 本次会话不保存，继续可用 | “这次记不住，下次再试。” |
| 用户修改系统时间 | 只重算时段，不发放奖励 | 无 |
| 重置时误触 | 二次确认 + 明确“不可撤销” | “确定要让它重新认识你吗？” |

### 3.5 与麦克风联动（P1，契约保留、未实现）

> 本轮不实现 UI/采集；仅保留状态机 MIC_START/SUCCESS/CANCEL/ERROR，作为下一阶段契约。以下为 P1 目标，AC-22~26 标 P1/未覆盖。

**功能描述**：用户使用外设麦克风时，宠物用表情和动作回应：倾听、得意、关心；但不显示转写内容、不干扰录音。

**用户故事**：作为用户，我希望说话时宠物在听、完成后为我高兴，以便工具操作也有陪伴感。

**业务规则**

1. 开始录音：若在睡觉则轻轻醒来；竖耳、看向用户；不出气泡。
2. 倾听中：轻微呼吸/摆动，停止随机 idle；不遮挡波形、计时、取消区。
3. 转写成功：2 秒得意/开心 + 少量闪光；可出一句“收到。”；不显示转写全文。
4. 取消：眨眼后回到之前心情；不出气泡、不表达失望。
5. 失败：歪头/耳朵下垂 1.5 秒；可说“没听清，再来一次？”；不责怪用户。
6. 麦克风状态优先于心情；录音结束后恢复录音前的心情，除非成功/失败触发了短暂情绪。
7. 宠物渲染失败不影响麦克风；麦克风失败也不改变宠物长期心情。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 录音权限被拒 | 宠物回到 idle；不追问 | 麦克风模块负责提示 |
| 连接中断 | 宠物不表现“被抛弃”；回到 idle | 麦克风模块提示重连 |
| 转写超时 | 关心 1.5 秒后恢复 | 麦克风模块给“再说一次” |

### 3.6 单竖屏布局（P0）

**功能描述**：手机端只做竖屏舞台，不再支持横屏/支架/手持双姿态；宠物、气泡与麦克风胶囊按竖屏安全区排布。

**用户故事**：作为用户，我把手机竖着放在桌边或拿在手里，宠物和「按住说话」都在顺手的位置，不需要旋转手机。

**业务规则**

1. 只支持竖屏；Android Activity 锁定 `portrait`，旋转不改变界面。
2. 宠物水平居中、略偏上；宠物/气泡/麦克风按安全区排布，热区规则已随触摸互动下线。
3. 麦克风是 56px 高、`min(86vw,360px)` 宽的胶囊；录音/处理状态在同一胶囊内，不再出现独立录音卡片；取消只保留上滑手势。
4. 界面元素常显，由无操作自动变暗负责防烧屏；不再有 5 秒自动隐藏。
5. 不提供横屏、平板、折叠屏专用布局；这些场景按竖屏安全区展示，不做响应式改版。
6. 所有控件避开刘海、挖孔、圆角、手势条安全区。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 旋转手机 | 系统锁定竖屏，界面不变 | 无 |
| 安全区变化（分屏/系统栏） | 重新布局，不遮挡控件 | 无 |
| 按住录音时页面切换 | 取消录音，回到 idle | 麦克风模块提示 |

### 3.7 设置与关于（P0）

**功能描述**：用户可改名、开关震动、减少动效、开关屏幕常亮（含最长常亮时长）、调整自动变暗时长、重置宠物、查看隐私说明；声音暂未接入。

**业务规则**

1. 设置入口：舞台左上角图标，一次点击进入；聊天入口在右上（带连接状态点）。
2. 默认值：震动开、声音关、减少动效跟随系统、屏幕常亮开且最长 2 小时（0 = 不限）、无操作 5 分钟自动变暗；声音暂未接入（设置项 disabled）。
3. 改名规则同 3.1；保存后立即生效。
4. 重置需二次确认，明确不可撤销。
5. 关于页说明：宠物数据仅存本机、卸载会丢失、无账号/云同步；版本号；开源许可证入口（后续）。
6. 设置页不请求网络、不请求权限。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 保存失败 | 保留原值，提示重试 | “没保存上，再试一次。” |
| 重置中退出 | 不执行重置，保持原状 | 无 |

### 3.8 P1 / P2（本期不实现）

- **P1 AI 联动**：已作为独立 P1 功能先做，见 [hook PRD](../hook/PRD.md)；宠物只增加四态展示（静态/工作中/等你决定/完成），不做任务看板、不显示进度/步骤/错误详情。
- **P2 桌面宠物**：不在本期；桌面端只做麦克风状态。
- **P2 宠物触摸互动**：点击/抚摸/拖拽等交互整体延后，后续作为独立功能重新评审，不在本轮恢复。

### 3.9 与 AI 联动的关系（P1，独立 PRD）

- AI 四态是叠加在宠物舞台上的展示状态，不改变命名、精力、存档规则。
- 倾听优先于 AI 状态，结束后恢复；完成态不跨后台/重连补播。
- AI 状态不落盘；重启后等桌面快照。
- 详细规则见 [hook PRD](../hook/PRD.md) 与 [hook SPEC](../hook/SPEC.md)。

## 4. 非功能需求

| 类别 | 要求 | 验收标准 |
| --- | --- | --- |
| 性能 | 真机动画流畅 | 60fps；单帧主线程 <16ms；长任务 <50ms |
| 响应 | 按钮反馈快 | ≤100ms 有可见反馈 |
| 加载 | 宠物页进入后可操作 | ≤1.5s；资源懒加载 |
| 内存 | 中端安卓稳定 | 宠物页常驻 ≤150MB `[待基线]` |
| 电量 | 支架模式可长时间放置 | 30 分钟掉电 ≤5% `[待基线]`；低电量降频 |
| 隐私 | 宠物不联网、不录音 | 无网络请求；不请求麦克风/通知权限 |
| 持久化 | 重启不丢关键状态 | 名字/心情/设置恢复；损坏可回退 |
| 兼容性 | Realme RMX3370 / Android 13（竖屏） | 16:9、20:9 竖屏不遮挡、不滚动 |
| 无障碍 | 可感知、可操作 | 标签、对比度、减少动效、非颜色单一提示 |
| 可靠性 | 降级可用 | 动画失败有静态替代；存储失败不阻塞 |

## 5. 数据需求

事件口径与隐私规则见 [product/metrics.md](../../product/metrics.md)。本功能事件：

| 事件 | 触发 | 关键属性 | 用途 |
| --- | --- | --- | --- |
| `pet_open` | 宠物页进入前台 | `mood`, `energy_bucket` | 使用频率 |
| `pet_name_set` | 命名/改名 | `source`（default/custom），不记名字 | 命名完成率 |
| `pet_bubble` | 气泡展示/关闭 | `trigger`, `copy_id`, `dismissed` | 打扰度 |
| `pet_mic_react`（P1） | 麦克风引发反应 | `state` | 下一阶段 |
| `pet_reset` | 重置 | 无 | 重置使用 |

不记录：宠物名字、聊天、音频、转写、目标应用、剪贴板。事件仅存本机，默认保留 30 天，可清除。

## 6. 验收标准（核心）

| 验收 ID | 场景 | Given | When | Then |
| --- | --- | --- | --- | --- |
| PET-AC-01/03 | 首次命名 | 首次进入宠物页 | 输入名字并确认/跳过 | 使用新名字或默认名；`onboarded=true`；重启保留 |
| PET-AC-06 | 待机动画 | 宠物页前台 30 秒无操作 | 观察 | ≥3 次眨眼 + ≥1 次非眨眼随机动作 |
| PET-AC-07 | 回来问候 | 离开 6 小时后回前台 | 进入宠物页 | 3 秒“想你”问候；夜间睡眠优先 |

| PET-AC-48 | 触摸无反应 | 宠物 idle | 点按/长按/来回滑动宠物 | 无气泡/震动/爱心/姿态切换；不写存档 |
