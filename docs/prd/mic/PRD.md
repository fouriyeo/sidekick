# PRD：随身麦 · 外设麦克风

**版本** v0.2 · **日期** 2026-10-31 · **状态** 已实现（P0，真机/权限矩阵继续回归）
**平台** 手机端（优先横屏、不强制横竖屏）采集 + 桌面 macOS 转写/输入
**关联** [SPEC](./SPEC.md) · [ACCEPTANCE](./ACCEPTANCE.md) · [音频工程方案](../../engineering/audio-pipeline.md) · [交互规范](../../standards/ux.md)

## 0. 一页摘要

按住手机说话，松开后文字出现在电脑当前光标处。手机从“第二块屏”变成电脑的无线麦克风，服务 AI 语音输入：写 prompt、口述需求、让 AI 改代码，不用把手从键盘上移开。

- **P0**：按住说话、上滑取消、本机转写、自动粘贴/仅复制、权限引导、横屏双姿态、状态反馈。
- **不做**：系统级虚拟麦克风、云转写、后台录音、音频历史、语音指令。
- **铁律**：只输入文本，**绝不自动回车、绝不自动发送**；录音时始终可见；原始音频不落盘。

## 1. 背景与目标

### 1.1 背景

- 与 AI 结对时，prompt 越来越长；键盘输入慢，语音输入工具又要切换应用。
- 手机本来就放在桌边，横屏、有麦克风、有网络；把它当无线麦克风，比再买一个硬件更顺手。
- Sidekick 已有局域网连接和手机 App；麦克风是第一个高频效率功能，也是宠物之外的第二根支柱。
- 不做会怎样：手机仍只是聊天/通知壳，缺少每天使用的理由；做了会怎样：用户每天多次拿起手机说话，宠物也有了“听你说话”的情绪场景。

### 1.2 目标用户

| 用户角色 | 特征 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| AI 结对开发者 | macOS、Qoder/Claude Code/终端 | 不离开键盘，快速把一句话变成 prompt | 写需求、改 bug、解释代码 |
| 内容创作者/研究者 | 长段落写作、口述比打字快 | 快速记录一段话，自动进入编辑器 | 写文档、整理思路 |
| 隐私敏感用户 | 不愿把语音上传云端 | 本机转写、按住才录、可随时取消 | 处理敏感项目 |

非目标：需要会议/录音软件虚拟麦克风的用户（P2）、公共网络用户、期待云同步/多语言的高级用户。详见 [product/users.md](../../product/users.md)。

### 1.3 目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
| --- | --- | --- | --- |
| 输入更快 | 松手 → 文本出现在目标应用 p95（≤10 秒语音） | ≤3s `[假设]` | 本地计时事件 |
| 一次可用 | 转写后无需手动大改 | ≥80% `[假设]` | 试用记录 + 自我修正次数 |
| 形成习惯 | 周均成功语音输入/活跃设备 | ≥10 次 `[假设]` | `mic_result` |
| 不打扰 | 按下 → 倾听反馈 | ≤100ms | 真机测量 |
| 可信 | 原始音频落盘/自动发送/错误目标应用 | 0 | 代码审查 + 抓包/文件检查 |
| 准确 | 30 句中英混合测试集字符准确率 | ≥90% `[假设]` | 固定测试集 |

指标口径见 [product/metrics.md](../../product/metrics.md)。所有目标值是假设，先测基线再校准。

按住手机说话，松手后文字出现在电脑光标处。

| 模块 | 包含 |
| --- | --- |

## 3. 功能详细设计

### 3.1 进入麦克风模式（P0）

**功能描述**：宠物界面始终有一个麦克风入口；连接正常时可按住说话，未连接时引导连接。

**用户故事**：作为用户，我希望在宠物界面直接按住说话，以便不切应用就能输入。

**业务规则**

1. 支架模式：底部居中胶囊“按住说话”；手持模式：右下圆形麦克风按钮；两种姿态都可见。
2. 未连接电脑时按钮禁用，点击打开连接引导；不自动开始录音。
3. 电脑端未启动/不可达：提示“电脑端还没准备好”，给重试/连接入口。
4. 首次使用前展示权限说明：只在按住时录、松手即停、不保存音频；用户确认后才请求系统权限。
5. 同一时间只允许一个录音会话；录音中再次按下无效。
6. 进入麦克风模式不需要切换到独立页面；宠物舞台保留，作为倾听反馈。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 未连接 | 禁用按钮，打开连接引导 | “先连接电脑，再按住说话。” |
| 电脑端版本不支持 | 禁用并提示更新 | “电脑端需要更新。” |
| 连接中断 | 停止当前录音并丢弃 | “连接断了，这段没有发送。” |
| 重复按下 | 忽略第二次 | 无 |

### 3.2 按住说话（P0）

**功能描述**：按下即录，松手即停；上滑取消；有最短/最长时长和后台保护。

**用户故事**：作为用户，我希望按住就说、松开就结束，以便像对讲机一样自然地口述。

**业务规则**

1. 按下即进入倾听/准备状态，视觉反馈 ≤100ms；首次权限弹窗期间显示“准备中”，不需要先点“开始”。
2. 按住期间上滑 ≥48dp 进入取消区；在取消区松手 → 取消并丢弃音频。
3. 松手（非取消区）→ 停止录音并开始转写。
4. 按下 <300ms 释放 → 视为误触，不转写，提示“按住说话”。
5. 单次最长 60 秒；50 秒时轻震 + 倒计时；60 秒自动停止并转写。
6. 录音中始终显示：脉冲指示、计时、“上滑取消”。
7. App 进入后台、锁屏、来电、失去麦克风焦点 → 立即停止并丢弃；回来后提示“已取消”。
8. 不允许后台录音；不允许锁屏继续录；不允许静默重录。
9. 录音中宠物互动禁用；麦克风按钮优先。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 误触 <300ms | 不发送 | “按住说话。” |
| 麦克风被其他应用占用 | 停止，提示占用 | “麦克风被其他应用占用了。” |
| 录音中来电 | 停止并丢弃 | “来电了，这段没有发送。” |
| 录音中切后台 | 停止并丢弃 | “已取消（App 进入后台）。” |
| 60 秒上限 | 自动停止并转写 | “到 1 分钟了，先转这段。” |

### 3.3 桌面转写与文本输入（P0）

**功能描述**：电脑接收语音，在本机转成文字，并输入到用户当前使用的 AI 工具/编辑器；不安全时只复制。

**用户故事**：作为用户，我希望说完后文字直接出现在光标处，以便不用切换窗口、不用手动粘贴。

**业务规则**

1. 本期默认在本机转写，不上传云端；原始音频在转写完成后立即丢弃。
2. 录音开始时记录当前前台应用；插入前再次确认前台应用未变。
3. 目标应用变化 → 不自动输入，只复制到剪贴板并提示。
4. 当前焦点不是可编辑输入框 → 只复制并提示。
5. 检测到密码/安全输入框 → 只复制，绝不自动输入。
6. 默认输入方式：自动粘贴到光标处（需桌面辅助功能权限）；权限未开/失败 → 仅复制。
7. **绝不自动按回车/Return，绝不自动发送/提交**；只输入文本。
8. 空转写/过短 → 不输入，提示“没听清，再说一次”。
9. 单次转写超过 2000 字 → 截断到 2000 字并提示；不自动分段提交。
10. 桌面显示不抢焦点的状态浮层：倾听中 / 转写中 / 已输入 / 已复制 / 失败；P0 为应用内浮层，独立窗口 P1。完成后 2 秒收起，失败保留 5 秒。
11. 输入成功后提示“已输入 · ⌘Z 撤销”；撤销使用系统能力，不自建撤销栈。
12. 不重复输入同一段；重试需要重新录音（本期不保存音频）。
13. 语音模型在本机下载/选择/存储；无模型时明确提示去桌面设置下载，不缓存音频。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 辅助功能权限被拒 | 仅复制 | “已复制。要自动输入，请允许 Sidekick 的辅助功能。” |
| 目标窗口变化 | 仅复制 | “你切到了别的窗口，文字已复制。” |
| 密码框/安全输入 | 仅复制 | “当前是密码框，已复制，未自动输入。” |
| 无焦点输入框 | 仅复制 | “没找到输入框，已复制到剪贴板。” |
| 本机转写失败 | 不输入，给重试 | “没听清，靠近一点再说一次。” |
| 文本超长 | 截断并提示 | “太长了，先输入前 2000 字。” |
| 桌面端崩溃 | 手机显示失败；音频丢弃 | “电脑端没响应，这段没有发送。” |

### 3.4 手机端状态反馈（P0）

**功能描述**：手机显示录音、转写、完成、失败状态，并保留最近一次结果卡片，方便确认。

**用户故事**：作为用户，我希望知道这段有没有成功、去了哪里，以便放心继续工作。

**业务规则**

1. 状态：idle、listening、processing、delivered、error；同一时间只显示一个主状态。
2. 倾听中：波形 + 计时 + 上滑取消 + 脉冲指示。
3. 转写中：三点/旋转 + “转写中…”；禁止再次录音，直到完成/失败/超时（10 秒）。
4. 完成：对勾 + “已输入”或“已复制到电脑”；最近一次转写卡片显示 10 秒，最多 2 行，可展开/复制。
5. 失败：一句人话 + “再说一次”按钮；不自动重录、不保存音频。
6. 最近一次转写只在内存；重启 App 清空；不进入历史列表。
7. 不显示原始音频、波形回放、录音文件。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 转写超时 10 秒 | 进入失败，丢弃 | “电脑端没回应，再说一次？” |
| 完成但自动粘贴失败 | 显示“已复制” | “已复制到电脑，去粘贴吧。” |
| 连续失败 2 次 | 建议检查连接/权限 | “检查一下连接和麦克风权限。” |

### 3.5 权限与连接引导（P0）

**功能描述**：在需要时解释并请求手机麦克风、桌面辅助功能权限；连接异常时给出可执行路径。

**用户故事**：作为用户，我希望知道为什么需要权限、被拒后怎么改，以便不被卡住。

**业务规则**

1. 手机麦克风：首次按下时请求；先展示用途说明，再弹系统权限。
2. 手机麦克风被拒：按钮仍显示，点击后打开引导页；提供“去系统设置”入口或步骤。
3. 桌面辅助功能：首次自动粘贴前请求；被拒则降级为仅复制，并在设置里提供“重新授权”。
4. 连接：优先自动重连；失败后给“重新连接”按钮；不无限弹窗。
5. 电脑端未启动/版本不匹配：给出明确提示，不静默失败。
6. 不在未连接时缓存音频、不在后台排队重发。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 麦克风权限永久拒绝 | 引导系统设置；不能录音 | “去系统设置打开麦克风权限。” |
| 辅助功能权限被拒 | 仅复制；不阻塞录音 | “已复制；要自动输入请授权。” |
| 自动重连失败 | 停止尝试，显示手动入口 | “连不上，检查 Wi-Fi 或电脑端。” |
| 电脑端版本旧 | 禁用麦克风 | “电脑端需要更新。” |

### 3.6 横屏双姿态（P0）

**功能描述**：同一横屏界面支持支架和手持；麦克风入口的位置、大小、取消方式随姿态变化。

**用户故事**：作为用户，我希望手机放支架时伸手就能按，拿起来时拇指够得着。

**业务规则**

1. 支架：底部居中胶囊（高 72dp），上滑取消；界面元素 5 秒淡出。
2. 手持：右下圆形按钮（直径 96dp），左下取消 + 上滑取消；界面元素常显。
3. 姿态切换中不打断录音；录音结束后再切布局。
4. 竖屏正在录音 → 停止并丢弃，提示横屏后再试。
5. 所有控件避开安全区；麦克风不被宠物/气泡遮挡。
6. 误触保护：按下 <300ms 不发送；上滑有取消区高亮。

**异常处理**

| 场景 | 处理 | 用户提示 |
| --- | --- | --- |
| 录音中拿起手机 | 保持布局，结束后切换 | 无 |
| 竖屏录音 | 停止丢弃 | “横屏后再说一次。” |
| 安全区变化 | 重排控件，不遮挡 | 无 |

### 3.7 P1 / P2（本期不实现）

- **P1 锁定说话/连续听写**：双击锁定、点击停止；需要 VAD 和流式转写。
- **P1 语音指令/格式化**：口述标点、段落、列表；自定义词典（代码术语）。
- **P1 多语言**：中英混说优化、语言选择。
- **P1 转写预览**：桌面先预览再输入；会变慢，需验证。
- **P2 系统级虚拟麦克风**：会议/录音软件可用；需 macOS 虚拟声卡驱动。
- **P2 BLE 通道**：网络隔离场景。
- **P2 iOS**：后台与音频限制单独评估。

## 4. 非功能需求

| 类别 | 要求 | 验收标准 |
| --- | --- | --- |
| 延迟 | 按下反馈快；松手到输入可接受 | 反馈 ≤100ms；p95 ≤3s（≤10s 语音） |
| 准确性 | 中文为主，中英混说可用 | 30 句测试集字符准确率 ≥90% `[假设]` |
| 隐私 | 不落盘、不上云、可见指示 | 无音频文件；无全文日志；录音指示常显 |
| 安全 | 不自动发送、不输错窗口 | 0 次回车/发送；目标变化/密码框仅复制 |
| 稳定性 | 断网/后台/来电可恢复 | 无崩溃；10 秒内回到 idle |
| 电量 | 连续使用不过热 | 30 分钟混合使用掉电 ≤8% `[待基线]` |
| 兼容性 | Realme Android 13 + macOS 13.3+ | 真机通过；WebView ≥111 |
| 无障碍 | 状态可读、可操作 | 标签、对比度、减少动效、非颜色单一提示 |
| 网络 | 可信局域网 | 公共网络明确警告；P1 配对/加密 |

## 5. 数据需求

口径见 [product/metrics.md](../../product/metrics.md)。本功能事件：

| 事件 | 触发 | 关键属性 | 用途 |
| --- | --- | --- | --- |
| `mic_start` | 开始录音 | `posture`, `source`（button/lock） | 使用场景 |
| `mic_stop` | 停止录音 | `reason`（release/cancel/timeout/background/disconnect）, `duration_bucket` | 取消原因 |
| `mic_result` | 转写/输入完成 | `outcome`（inserted/copied/failed）, `latency_ms`, `text_length_bucket` | 成功率/延迟 |
| `mic_error` | 失败 | `code`（permission_denied/no_connection/asr_failed/target_mismatch/secure_input/insert_failed） | 失败分布 |
| `mic_permission` | 权限请求结果 | `type`（phone_mic/accessibility）, `result` | 权限摩擦 |
| `insert_result` | 文本输入 | `mode`（auto/clipboard）, `target_category`（editor/terminal/browser/unknown）, `success` | 输入可靠性 |

不记录：原始音频、完整转写、剪贴板内容、目标应用名称、宠物名字。事件仅存本机，默认 30 天，可清除。

## 6. 验收标准（核心）

| 编号 | 场景 | Given | When | Then |
| --- | --- | --- | --- | --- |
| MIC-AC-01 | 未连接 | 手机未连接电脑 | 按麦克风 | 不录音；显示连接引导 |
| MIC-AC-02 | 按住说话 | 已连接、权限已给 | 按住 3 秒后松开 | 100ms 内进入倾听；松手后转写并输入 |
| MIC-AC-03 | 上滑取消 | 录音中 | 上滑到取消区松开 | 不转写、不输入；提示已取消 |
| MIC-AC-04 | 误触 | idle | 按下 <300ms 松开 | 不发送；提示“按住说话” |
| MIC-AC-05 | 最长时长 | 录音中 | 持续到 60 秒 | 50 秒提醒；60 秒自动停止并转写 |
| MIC-AC-06 | 后台停止 | 录音中 | 按 Home/锁屏 | 立即停止并丢弃；回来提示已取消 |
| MIC-AC-07 | 本机转写 | 已连接 | 说 10 秒中文 | 文字出现在当前光标处；无回车/发送 |
| MIC-AC-08 | 目标窗口变化 | 录音开始后切到别的应用 | 松手完成 | 不自动输入；只复制并提示 |
| MIC-AC-09 | 密码框 | 焦点在密码框 | 完成转写 | 不自动输入；只复制并提示 |
| MIC-AC-10 | 权限被拒 | 麦克风权限拒绝 | 按麦克风 | 不录音；给系统设置引导 |
| MIC-AC-11 | 姿态 | 支架/手持 | 切换 | 布局切换；按钮不跳位；不打断录音 |
| MIC-AC-12 | 隐私 | 使用 30 分钟 | 检查存储/抓包 | 无音频文件、无云端上传、无全文日志 |
| MIC-AC-13 | 模型 | 首次使用/无模型 | 按麦克风 | 提示去桌面设置下载；不缓存音频 |
| MIC-AC-14 | 模型 | 设置页 | 下载/选择/删除 | 进度可见；完成后可切换；删除后提示重新下载 |

完整用例见 [ACCEPTANCE.md](./ACCEPTANCE.md)。

## 8. 风险与依赖

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| Android WebView 麦克风权限/采集不稳定 | 高 | 阻塞 P0 | 先 spike；准备原生采集插件方案 |
| 本机 ASR 中文/代码术语准确率不够 | 中 | 体验差 | 固定 30 句测试集；可选模型/引擎对比 |
| macOS 辅助功能权限摩擦 | 高 | 自动粘贴失败 | 默认降级复制；清晰引导；设置可重授权 |
| 输错窗口/密码框 | 中 | 隐私/数据风险 | 目标窗口校验、安全输入检测、只复制 |

| 电量/发热 | 中 | 长时间不可用 | 60 秒上限、后台停止、低功耗编码 |
| 用户担心被偷录 | 中 | 信任崩塌 | 按住才录、可见指示、无后台、无落盘 |

## 9. 开放问题

- 默认“自动粘贴”还是“先复制、用户手动粘贴”？当前建议自动粘贴 + 权限降级。
- 本机转写选 macOS 原生语音还是跨平台本地模型？需 spike 对比准确率/延迟/体积。
- 中英混说和代码术语的优先级；是否 P0 就做自定义词典？
- 60 秒上限是否够用？锁定说话是否提前到 P1？
- 桌面浮窗用独立小窗还是系统通知？当前建议独立、不抢焦点。
- 配对/加密在麦克风之前还是之后做？当前 P1。
- 转写结果是否需要在手机端保留更久？当前 10 秒、仅内存。
