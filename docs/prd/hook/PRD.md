# PRD：AI 联动（Hook）

**版本** v0.1 · **日期** 2026-11-02 · **状态** 草稿（待实现验收）
**平台** 桌面端设置 + 手机端宠物；第一期只接 DeepSeek Harness
**关联** [SPEC](./SPEC.md) · [ACCEPTANCE](./ACCEPTANCE.md) · [宠物 PRD](../pet/PRD.md) · [产品原则](../../product/principles.md)

## 0. 一页摘要

手机上的宠物不只陪伴，也当电脑 AI 的「状态外设」：AI 开始工作、等用户决定、完成任务时，手机宠物用明显不同的动作、文案和短音效表达。

- **P0**：桌面「AI 联动」页、DSH 本地脚本注入、状态协议、手机四态动作、三个音效、状态快照与断连恢复、手机会话列表（标题/状态/当前工具动作/完成保留/本地清除）、反问一键唤起电脑 DSH。
- **不做**：手机回答 AI、文本消息、关闭 App 后推送、任务详情/进度、Claude Code/Qoder（后续）。
- **成功**：状态 1 秒内到手机；四态 3 米外不看文字也能区分；不漏报显式提问；不泄露任何对话内容。

## 1. 背景与目标

### 1.1 背景

- DSH 把 AI 工作过程关在电脑里；用户离开电脑或低头看手机时，不知道 AI 在忙、在等自己，还是已经完成。
- 现有手机宠物只有陪伴和 AI 联动；AI 状态映射在宠物 PRD 里原本是 P2，现在作为独立 P1 功能先做最小闭环。麦克风与宠物已解耦（D77），不再互相驱动。
- 直接依赖第三方 hook 插件会引入安装、版本和维护风险；用户明确希望「自己写个脚本配置进去」。因此采用本地 `.mjs` 插件 + profile patch 注入。
- 不做会怎样：手机仍是孤立的宠物；做了会怎样：宠物与电脑 AI 产生真实联系，为后续手机回答 AI 提问打基础。

### 1.2 目标用户

| 用户 | 特征 | 核心诉求 | 场景 |
| --- | --- | --- | --- |
| AI 结对开发者 | macOS + DSH，手机放支架 | 抬头就知道 AI 在忙/等自己 | 写需求、跑任务、等审批 |
| 长时间写作者 | 手机在桌边，不想盯电脑 | 低打扰的进度感 | 查资料、等生成 |
| 桌搭用户 | 在意宠物表现 | 状态变化有生命感、不呆板 | 工作区摆设 |

非目标：需要任务看板/进度百分比的用户、公共网络用户、需要手机回答 AI 的用户（下一期）。

### 1.3 目标与成功指标

| 目标 | 指标 | 目标值 | 验证 |
| --- | --- | --- | --- |
| 状态及时 | 事件到手机可见延迟 | p95 ≤ 1s | 真机录屏/日志 |
| 一眼能懂 | 3 米外不看文字识别四态 | ≥ 80% | 5 人小测 |
| 不漏提问 | 显式提问/审批 5 次 | 0 漏报 | 真机用例 |
| 不误报 | 普通工具调用 10 次 | 0 误报 asking | 真机用例 |
| 完成节奏 | 完成态持续 | 3s ± 0.3s | 录屏计时 |
| 不打扰 | 默认声音关闭；提问音最多 2 次 | 100% | 设置/日志 |
| 隐私 | 对话/提示词/路径/参数外发 | 0 条 | 抓包/日志审计 |

## 2. 范围

### 2.1 P0

| 模块 | 包含 |
| --- | --- |
| 桌面 AI 联动页 | 开关、首次安装、连接状态、当前状态、事件日志、模拟、隐私、修复/移除 |
| DSH 本地脚本 | 写脚本 + patch；热开关；只发状态；失败不拖垮 DSH |
| 状态协议 | `status` / `status.request`；完成态 3 秒与快照 |
| 手机四态 | 静态/工作中/等你决定/完成；动作、文案、轻震、无障碍 |
| 声音 | 开工/提问/完成三音效；默认关；设置试听；录音/后台静音 |
| 会话列表 | 宠物页上方收起 1 条 / 展开 5 条滚动；显示标题、状态与工作中的当前工具动作；完成保留到清除；新反问自动展开 |
| 清除与唤起 | 手机本地清除标记（有新事件会再出现）；点「等你决定」会话把电脑 DSH 切到前台（没开则启动） |
| 恢复 | 重连/回后台快照；DSH 退出 15 秒内回静态、列表清空 |

### 2.2 P1 / 不做

- 手机回答 AI 提问（`answer` 回传、DSH hook 结果注入）。
- 文本消息：DSH 回复发手机、手机发文本给 DSH。
- Claude Code / Qoder 接入（协议 `source` 预留）。
- 关闭 App/后台推送通知。
- 任务详情、步骤、token、错误态、进度条。
- 子代理完成合并（`tree/settled`）；P0 只聚合顶层会话，已知可能提前完成。
- 专门设计的小宠物叫声资产、分事件开关、音量、Android 音频焦点/勿扰（P1）。
- 桌面端音效、多电脑/多手机配对鉴权。

## 3. 功能规则

### 3.1 桌面「AI 联动」页（P0）

1. 桌面右侧导航第三个 Tab「AI 联动」；不放进设置 Sheet。
2. 页面展示 DSH 卡片：开关、连接状态、profile、当前宠物状态、进行中会话数、最近心跳。
3. 首次开启必须确认三件事：会写哪些文件、不装 npm 包/不读对话、首次需要重启 DSH。
4. 开关语义：
   - 未安装：点击 → 确认 → 安装并开启 → 等待 DSH 重启/连接。
   - 已安装：点击只写 `enabled`，1 秒内热生效。
   - 关闭：脚本停止上报，宠物回静态；保留安装，便于下次秒开。
5. 「移除联动」二次确认；移除 patch 标记、脚本、配置；DSH 下次启动不再加载。
6. 错误必须给路径和下一步；不能只显示「失败」。
7. 本机模拟按钮可以推送四态到手机，用于不启动 DSH 时验收；模拟状态会被下一次 DSH 心跳覆盖。
8. Claude Code / Qoder 只显示灰色「后续版本」，不做假开关。
9. 不显示任务内容、模型名、文件路径；只显示状态、会话数和时间。

### 3.2 DSH 接入（P0）

1. 只支持 DeepSeek Harness 桌面/网页 profile；默认选运行中的 profile，找不到默认 `desktop`。
2. 不安装第三方 npm 插件；Sidekick 写一个本地 `.mjs` 并插入 profile `cordis.patch.yml`。
3. 写入前备份 patch；写入失败必须回滚；不得破坏用户已有配置。
4. 插件不在 DSH required 列表；加载失败只警告，不阻断 DSH 启动。
5. 首次写入后需要重启 DSH 一次；Sidekick 轮询心跳判断是否生效。
6. 同时运行 desktop/web 时只允许选一个 profile；脚本按配置 profile 自检，另一个不上报。
7. DSH 升级导致事件变化时，脚本静默不拖垮 DSH；页面显示「已连接但无事件」，提供修复/移除。

### 3.3 状态映射（P0）

| DSH 事件 | 宠物状态 |
| --- | --- |
| 顶层会话 `turn/start` | 工作中 |
| `approval/asked` / 提问类 `tool/call`（`ask_user_question`、`exit_plan_mode` 等） | 等你决定 |
| `approval/decided` / 提问结果 / 用户回复 | 回工作中 |
| `turn/end` completed | 完成 3 秒 |
| `turn/end` blocked | 等你决定 |
| `turn/end` error/aborted/max-tokens/interrupted | 静态（P0 不显示错误态） |
| DSH 退出/心跳超时 15 秒 | 静态 |

规则：

1. 聚合所有顶层会话：任一 asking → 等你决定；否则任一 working → 工作中；否则完成脉冲未过期 → 完成；否则静态。
2. 完成脉冲 5 秒内最多一次；完成态只持续 3 秒。
3. 子代理 P0 不计数、不驱动 asking/completed；已知父 turn 交给后台子代理时可能提前完成。
4. 只认显式提问/审批；模型在回复末尾问一句不算。
5. 命名庆祝/休息时宠物让位；结束后恢复 AI 状态；完成态不补播。录音不再改变宠物姿态（宠物与麦克风已解耦，D77）。
6. 夜间 AI 状态会唤醒宠物；空闲后恢复睡眠判定。

### 3.4 手机四态（P0）

1. 四态：静态、工作中、等你决定、完成（3 秒）；都要有动作，不能只是文字/颜色变化。
2. 静态是「慢而活着」，不是冻结；工作中要非常繁忙；等你决定要着急、左右找人；完成要爆发庆祝。
3. 四态在轮廓、速度、道具、主色上必须明显不同；减少动效和夜间也要能区分。
4. 状态文案是辅助，不是唯一信号；位置不遮挡宠物/麦克风/安全区。
5. 完成态 3 秒后回到正确稳定态（工作/等你决定/静态）。
6. 重连/回前台只恢复稳定态；过期的完成态不补播。
7. 不持久化 AI 状态；重启 App 后等桌面快照。

### 3.5 声音（P0）

1. 三个事件：开始工作、等你决定、完成；各一个短音效（≤ 420ms）。
2. 默认关闭；宠物设置可开启，并提供三个试听按钮。
3. 只在 App 前台、宠物页可见、麦克风未录音时播放；后台/录音静音。
4. 开工音只在从静态/睡眠进入工作中时响；完成/提问回到工作不响。
5. 提问音最多 2 次：进入时一次，12 秒未解决再提醒一次；解决后不再响。
6. 完成音每次完成脉冲只响一次；不连播、不循环。
7. P0 用 Web Audio 合成音，不新增音频文件；系统静音/勿扰可能无法完全遵守，P1 接原生提示音/音频焦点。

### 3.6 隐私与安全（P0）

1. 只同步 `state / sessions / ts / resume` 与 `sessionList`（会话 id、标题、状态、askKind、lastEventAt、completedAt、粗粒度工具类别 `tool`）；不同步提示词、回复、工具参数、文件路径、cwd、模型名或工具名原文。标题是本功能新增的内容类字段，单行 ≤80 字符，不写日志、不落盘；`tool` 是插件本地归一后的固定枚举（bash/read/edit/search/web/agent/plan/tool），不是工具名透传。
2. 桌面回环接收端口只绑 `127.0.0.1`；token 校验；非法请求不上报。
3. 配置 `0600`；事件日志只在内存，最多 20 条。
4. 声音只在手机本地合成，不传输音频、不录音。

### 3.7 手机会话列表与唤起（P0）

1. 列表只放在手机宠物页：宠物上方、默认收起只显示 1 条（优先级 asking > working > completed > idle）；点击收起条展开，展开默认显示 5 条，超出内部滚动。
2. 每行显示状态点、会话标题（缺失用「新会话 + id 后 4 位」）、状态文案和相对时间；工作中行显示小圆环 spinner + 「正在<工具动作>」（运行命令/阅读文件/修改文件/搜索代码/查资料/处理子任务/整理计划/使用工具；无工具显示「正在思考」）；「等你决定」行珊瑚色并显示外链提示。
3. 新出现「等你决定」的会话自动展开一次；用户手动收起后，只有新的 asking 会话才再次自动展开。
4. 完成态一直保留到手动清除或该会话开始新一轮；列表最多展示 50 个存活顶层会话，子代理不显示。
5. 每行有清除按钮：只清手机端这条会话的状态记录，不是黑名单；该会话 `lastEventAt` 更新后自动重新出现。清除标记只存 id 与时间，重启 App 仍有效。
6. 「等你决定」的会话点击后，手机发 `focus.request`，电脑把 DSH 切到前台（未启动则启动）；只唤起，不自动回答、不发送任何内容、不定位到具体会话。
7. 会话全部清除或 DSH 退出时列表隐藏、宠物回原位；断连立即清空可见列表，重连后等桌面快照。
8. 列表不展示提示词、回复、工具参数、文件路径、cwd、模型名或工具名原文；工作行动作只显示固定枚举对应的中文词。

## 4. 非功能需求

| 类别 | 要求 | 验收 |
| --- | --- | --- |
| 延迟 | 状态变化到手机可见 p95 ≤ 1s | 真机日志/录屏 |
| 性能 | 宠物页 60fps；动画只 transform/opacity | Realme 真机 |
| 恢复 | DSH 退出 15s 内静态；恢复 10s 内复原 | 杀进程用例 |
| 兼容 | 旧版手机忽略 status / `tool`；旧插件不报 `tool` 时工作行显示「正在思考」；旧版 DSH 不支持时页面可修复/移除 | 回归 |
| 安全 | 回环 + token；无内容外发 | 抓包/日志 |
| 无障碍 | aria-live；不只靠颜色；减少动效 | 组件/真机 |
| 可靠 | DSH 插件失败不阻断 DSH 启动 | 日志/手工 |

## 5. 数据与埋点

- 本功能默认不新增云端埋点；事件日志只在桌面内存。
- 如需本地统计，只记录 `hook_install`、`hook_toggle`、`hook_state`（state/source/延迟桶），不记录会话名/内容。
- 不记录：提示词、回复、工具参数、文件路径、模型名、工具名原文、token。

## 6. 风险与依赖

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| DSH 插件 API/事件变化 | 中 | 状态失效 | 自写脚本 + try/catch；spike；失败可移除；备选 dsh-hooks 插件 |
| profile patch 写入破坏配置 | 低 | DSH 起不来 | 标记块 + 备份 + 写前校验 + 移除顺序 |
| 首次必须重启 DSH | 高 | 体验中断 | 明确提示；之后热开关；P1 评估热加载 |
| 四态动作难产/太像 | 中 | 识别失败 | 先做轮廓/道具/速度验证；3 米识别测试 |
| 音效打扰/打断音乐 | 中 | 体验差 | 默认关；短音；真机测试；P1 原生提示音 |
| 子代理提前完成 | 中 | 状态不准 | P0 记录限制；P1 tree/settled |
| 自由文本提问漏报 | 高 | 少报 asking | 明确只认显式提问；P1 再评估 |

## 7. 开放问题

- P1 何时接手机回答 AI 提问（需要 ask 载荷、手机问答 UI、answer 回传、hook 结果注入）？
- P1 是否接 Claude Code / Qoder？优先级高于还是低于手机回答？
- 音效 P1 是否换成专门设计的宠物叫声资产？风格待定。
- 子代理完成合并（tree/settled）是否值得在 P1 做？
