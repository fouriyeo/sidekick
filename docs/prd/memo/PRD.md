# PRD：语音备忘录

> 实现状态（2026-11-08）：S1 手机独立 + S2 局域网镜像代码完成，待真机联调；Key 暂存 App 私有文件（Keystore 列 P1），手机固定官方端点。技术细节与偏差见 `docs/engineering/memo-pipeline.md`。

**版本** v0.1 · **日期** 2026-11-07 · **状态** 草稿（待评审）
**平台** Android 手机（主）+ macOS 桌面（只读镜像）
**关联** [SPEC](./SPEC.md) · [ACCEPTANCE](./ACCEPTANCE.md) · [技术方案](../../engineering/memo-pipeline.md) · [语音输入](../mic/PRD.md) · [D115](../../decisions.md)

## 0. 一页摘要

手机独立完成「录音 → 识别 → 归类 → 存成备忘录」：用户点一下开始录，说完再点结束；手机把音频分段送去百炼转写，再用 LLM 整理成标题、类型（备忘/待办/灵感）、摘要与待办项，存进手机本地库。全程不需要电脑，也不需要同一局域网；电脑只在同一 Wi-Fi 时接收镜像，用于回听和回看。

- **P0**：手机前台录音（锁屏/后台录音延后到 P1）；分段转写；AI 归类与摘要；本地 SQLite；列表/详情/播放；默认保留音频；失败可重试；离线待处理；电脑 Key 一次性下发；同局域网镜像同步。
- **不做什么**：完整 AI 会话（本期只做处理管道）、公网同步/账号、自定义分类体系、多设备、iOS、桌面编辑。
- **铁律**：录音默认保留但可关；内容只走用户自己配置的百炼；Key 只存手机 App 私有文件（0600；Keystore 列 P1）与电脑 `asr.json`（0600）；日志不打印转写/摘要/音频路径。

## 1. 背景与目标

### 1.1 背景

- 现有「语音输入」是一次性的：按住说 → 电脑转写 → 插入光标，**不落盘、不留历史、切后台即取消、最长 60 秒**（[mic PRD](../mic/PRD.md)）。它解决「把一句话变成电脑里的字」，不解决「把一段话留下来、以后再找」。
- 用户真实反馈：人可能不在电脑旁，手机有网；希望手机自己就能把语音变成可回看的备忘录。曾希望像录音卡一样锁屏也能录，但已决定**先不做**（P1，见 D118）。
- 不做的后果：灵感/会议结论只能散落在聊天记录、剪贴板与脑子里；做的后果：Sidekick 多一个「手机独立可用」的高频场景。

### 1.2 用户与场景

| 角色 | 特征 | 核心诉求 | 场景 |
| --- | --- | --- | --- |
| 个人开发者（主用户） | 手机不离身，电脑不一定在 | 走路/通勤时把想法说出来，回家能回看 | 路上、会议后、睡前 |
| 记录型用户 | 不想打开电脑 | 前台长录音，录完自动整理（锁屏录音 P1） | 开车前、散步、带孩子 |
| 电脑端用户 | 已装桌面端 | 在电脑上回听、搜索、复制 | 回到工位 |

非目标：需要多人协作、团队共享、跨设备实时编辑的用户。

### 1.3 目标与成功指标

| 目标 | 指标 | 目标值 | 监测 |
| --- | --- | --- | --- |
| 能录 | 录音会话成功率（开始→结束有音频） | ≥99% | 本地埋点 `[假设]` |
| 能出结果 | 录音到「已完成」的比例 | ≥95%（有网） | 本地埋点 |
| 快 | 点按到可录 p95 | ≤300ms | 计时 |
| 快 | 10 分钟录音处理 p95 | ≤90s | 计时 `[假设]` |
| 不丢 | 已完成备忘录本地丢失数 | 0 | 对账 |
| 同步 | 局域网同步成功率 | ≥99% | 对账 |
| 隐私 | 内容出现在日志/广播的次数 | 0 | 抓包 + 日志扫描 |

指标口径沿用 [product/metrics.md](../../product/metrics.md)；目标值先测基线再校准。

## 2. 需求概述

**一句话**：让手机自己成为一张能录、能懂、能存的录音卡，电脑负责存档与回看。

| 模块 | 包含 | 优先级 |
| --- | --- | --- |
| 入口 | 手机宠物页顶栏「备忘录」图标 → 全屏页；桌面侧栏「备忘录 ⌘3」一级页 | P0 |
| 录音 | 点按开始/结束；**前台/亮屏**；最长 2 小时；分片写盘 | P0 |
| 锁屏/后台录音 | 原生采集 + 前台服务 + 常驻通知（暂缓） | P1 |
| 处理管道 | 分段 ASR → LLM 结构化（标题/类型/摘要/待办） | P0 |
| 本地库 | SQLite + 音频文件；列表/详情/播放；删除 | P0 |
| AI 归类 | 固定三类：备忘 / 待办 / 灵感；可改标题与类型 | P0 |
| 音频保留 | 默认保留；设置可关；单条可删音频 | P0 |
| Key | 电脑一次性配对码下发 + 手动粘贴兜底；App 私有文件（Keystore P1） | P0 |
| 局域网同步 | 配对码/令牌、分块上传、确认后删本地、单写者 | P1 |
| 搜索/标签/批量/导出 | — | P2 |

## 3. 功能规则

### 3.1 入口与导航

1. 手机宠物页顶栏在「今日用量」与「聊天」之间新增「备忘录」图标（16px 线性，与现有图标同风格）；点击进入全屏备忘录页，左上「‹ 返回」，Android 返回键回宠物页。
2. 手机**不新增底部 tab**，不改 D80「宠物（根）/ 设置（二级）」与无底栏承诺；备忘录是第三个全屏二级页（与连接页、用量页同级）。
3. 桌面新增**独立一级页「备忘录 ⌘3」**（D123；桌面一级变为 6 个：概览/剪贴板/备忘录/用量/语音/设置）；「剪贴板」页保持单一职责，不再有「剪贴板 / 备忘录」分段。
4. 录音入口只在备忘录页内；宠物页麦克风仍是「语音输入」，两者互不影响。

### 3.2 录音（P0：仅前台）

1. 备忘录页底部居中一个 64px 圆按钮：点按开始录音，再点结束；录音中按钮变为停止态，旁边显示计时（`mm:ss`）与分片数。
2. **只支持前台录音**（App 在前台、屏幕亮着）；录音期间复用现有屏幕常亮能力（`set_keep_screen_on`）避免自动锁屏，停止即释放。
3. 录音中锁屏、切到其它 App、按系统返回键：**停止并保存**，提示「录音已停止并保存（需要保持 App 在前台）」。不做后台服务、不做常驻通知（P1，D118）。
4. 单次最长 2 小时；到点自动结束并保存，提示「已到 2 小时上限，录音已保存」。
5. 录音按 30 秒分片写盘（WebView 采集 + 分片经 Tauri 命令追加到文件）；进程被杀后下次启动扫描未完成分片，提示「上次录音可能中断，已恢复 N 片」。
6. 录音中点「取消」需二次确认（第一次变「再点一次」，2 秒内再点才删除）；取消只删本次音频，不产生备忘录。
7. 无麦克风权限时点录音 → 先走系统授权；拒绝后提示「需要麦克风权限才能录音」+「去设置」。
8. 来电/其它 App 抢占麦克风时：停止、写盘、提示「录音被系统打断，已保存」；不自动恢复。

### 3.3 处理管道

1. 录音结束后立即进入「待识别」，按分段顺序逐段调用百炼 ASR；每段完成后本地保留转写，全部完成后调用 LLM 结构化。
2. 状态：`recording`（录音中）→ `pending`（待识别）→ `transcribing`（识别中）→ `structuring`（整理中）→ `done`（完成）/ `failed`（失败，可重试）/ `offline`（等待网络）。
3. 无网络时进入 `offline`，回到有网自动开始；失败自动重试 1 次，仍失败显示「识别失败 · 重试」。
4. 处理中允许离开页面；锁屏/切后台后系统可能暂停处理，回前台继续（进度与已完成分段保留）。
5. 处理结果必须落库才显示「完成」；任一步失败不影响已完成的转写文本。
6. 不做实时上屏（P1 再评估）；录音中不显示转写。

### 3.4 归类与结构化

1. LLM 输出固定字段：`title`（≤20 字）、`type`（`memo` / `todo` / `idea`）、`summary`（≤80 字）、`todos`（0–5 条，每条 ≤40 字，可为空）、`tags`（0–3 个，P0 只展示不管理）。
2. 类型固定三类，中文文案：备忘录 / 待办 / 灵感；无 AI 结果时按 `memo` 兜底。
3. 用户可改标题与类型（详情页内联编辑，保存即生效）；摘要与待办项 P0 只读。
4. 待办项勾选状态 P0 不落库（P1 再做）；列表行对 `todo` 显示「N 项待办」。
5. 标题缺失时用转写首句截断；摘要缺失时不显示该块，不留空框。

### 3.5 列表与详情

1. 列表按创建时间倒序，分「今天 / 更早」两组；行显示：类型标签、标题（≤1 行）、摘要（≤1 行）、时间、同步状态点、录音时长。
2. 空态：「还没有备忘录。点下面的按钮，说点什么。」
3. 详情页：播放器（播放/暂停、进度、时长）、类型与标题、摘要、待办项、转写全文（可展开）、删除（整条，二次确认）。
4. 删除是二段式：第一次点「删除」变「再点一次删除」，再点才删；删除同时删音频文件与本地记录；已同步的条目删除后给桌面发墓碑。
5. 列表项左滑快捷删除（P1）；P0 只在详情页删。

### 3.6 音频保留

1. 设置页新增「备忘录」分组：**保留录音** 默认开；关闭后新录音在处理完成后自动删除音频，只留文字（已有条目不动）。
2. 详情页提供「删除录音」单独操作（保留文字），二次确认。
3. 设置页显示备忘录占用空间（音频 + 数据库）；不自动过期，不做云端备份。
4. 音频格式：16k mono PCM16 WAV（32KB/s，约 115MB/小时）；停止时回填 WAV 头；P2 再评估 AAC/Opus 压缩。

### 3.7 Key 与配置

1. 首次使用需要百炼 Key（ASR 与 LLM 共用）。手机提供两种方式：① 电脑下发；② 手动粘贴。
2. 电脑下发：桌面「设置 › AI 联动」同级的「语音」页新增「发送到手机」；点击生成 6 位一次性配对码（2 分钟有效），手机备忘录设置页输入配对码 → 电脑校验后一次性回 token + Key；错误 3 次作废。
3. 手机存储：MVP 落 App 私有目录 `memo/secure.json`（0600，Android 沙箱 + FBE；**Keystore 加密列 P1**）；界面只显示掩码（`sk-…abcd`）；提供「清除 Key」。
4. 手机不允许自定义 ASR/LLM 地址（固定官方域名），避免 Key 被重定向；模型 ID 可选（默认 qwen-plus 用于结构化）。
5. Key 失效/额度不足时：状态显示「Key 不可用」，待识别任务暂停并提示，不上传其它数据。

### 3.8 局域网镜像同步

1. 仅同一局域网、已配对（配对码换 token）的设备；无公网、无账号。
2. 手机是每条备忘录的所有者：创建、编辑、删除都只在手机；桌面只读。
3. 手机连上电脑后自动推送「未同步」条目（元数据 + 音频分块）；电脑确认收到（committed）后，手机标记「已同步」并保留本地音频（保留策略见 3.6）。
4. 音频分块上传：按字节偏移续传，整体 sha256 校验；未确认前断线可续传。
5. 删除：手机删除 → 发墓碑 → 桌面删除；桌面不能删除手机备忘录。
6. 同步状态词：`已同步` / `待同步` / `同步中`（仅上传中）；不显示百分比。
7. 电脑离线时手机完全可用；回网自动同步，不需要用户操作。

### 3.9 桌面镜像

1. 桌面一级「备忘录」页：列表显示类型、标题、摘要首行、时间、时长；点击打开只读详情 Dialog（播放器 + 全文 + 摘要 + 待办）。
2. 提供复制全文；不提供编辑、删除、重新归类。
3. 播放用系统音频能力；文件不存在时显示「音频不在本机」。
4. 同步来的条目不能反向覆盖手机（单向）。

### 3.10 隐私与数据

1. 音频与文本只存手机 App 私有目录与电脑 `~/.sidekick/`；不上传任何第三方（除用户配置的百炼 ASR/LLM）。
2. 日志只打事件与错误码，不打转写文本、标题、摘要、音频路径、Key。
3. 同步只在已配对的局域网连接上发生；协议消息定向下发，不广播给其它客户端。
4. 删除即删（文件 + 数据库行 + 墓碑同步）；不做回收站（P1 再议）。
5. 首次录音前展示一次告知：音频会发送到百炼做识别与整理。

### 3.11 失败与降级

| 情况 | 表现 | 处理 |
| --- | --- | --- |
| 无网络 | 状态「等待网络」 | 联网自动开始 |
| Key 未配置/失效 | 状态「Key 不可用」 | 去设置配 Key，任务保留 |
| ASR 单段失败 | 该段标红 | 整条「重试」，从失败段继续 |
| LLM 失败/超时 | 保留转写，类型兜底 `memo` | 可「重新整理」 |
| 存储不足 | 拒绝开始录音 | 提示清理空间 |
| 录音中锁屏/切后台 | 停止并保存 | 提示「需要保持 App 在前台」；后台录音见 P1 |
| 电脑离线 | 手机正常 | 回网自动同步 |
| 同步中断 | 「待同步」 | 续传，不重复 |

### 3.12 与语音输入的关系

1. 语音输入（麦克风按钮）保持原样：按住说话 → 电脑转写 → 插入光标；不写备忘录库、不保留音频。
2. 备忘录不自动插入电脑光标；需要时在详情页「复制全文」。
3. 两者共用麦克风权限与百炼 Key，但数据与失败处理互相独立。

## 4. 范围与优先级

| 优先级 | 内容 |
| --- | --- |
| P0 | 手机前台录音（亮屏、App 在前台）、分片转写、LLM 归类、本地库、列表/详情/播放、默认留音频、Key 下发/粘贴、失败重试、离线排队 |

2. 每个 P0 规则可验收：见 [ACCEPTANCE](./ACCEPTANCE.md)。
3. 失败路径写清：§3.11。
4. 隐私边界写清：§3.10 + [技术方案](../../engineering/memo-pipeline.md) §8。
5. 平台边界：手机主设备、桌面只读；桌面备忘录是独立一级页（D123），不共享页面代码。
6. 不做清单明确：§4。
7. 数据口径唯一：列表/详情/同步都以本地库为准，不造数。
8. 状态词统一：录音 5 态 + 条目 7 态，见 [SPEC](./SPEC.md)。
9. 可降级：Key/网络/LLM 失败都有兜底，不阻塞录音。
10. 文档同步：本 PRD + SPEC + AC + 技术方案 + 决策 D115/D118。

## 6. 风险

1. **录音体验受限（P0 已接受）**：只支持前台录音，锁屏/切后台会停止并保存；后台录音要原生采集 + 前台服务，延后到 P1（D118）。长录音的发热/耗电与成本估算同样延后到 P2，先不做。
2. **Key 下发链路**：现有局域网 WS 无 TLS、无鉴权；配对码只能降低风险，S3 必须补设备 token 与定向下发。
3. **LLM 质量不稳定**：标题/类型可能不准；P0 允许用户改，且保留原始转写。
4. **成本**：ASR 按时长、LLM 按 Token；长录音会持续产生费用，需要设置里显示当日用量（P1）。
5. **产品身份**：手机从「电脑外设」变成「独立录音卡」，需在 [product/scope.md](../../product/scope.md) 明确这是有意扩展，不是替代语音输入。

## 7. 里程碑

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| S1 | 手机前台录音（WebView 采集）+ 分片 ASR + LLM + 本地库 + 列表/详情 | 真机可录可看，离线可排队 |
| S2 | 局域网镜像同步 + 桌面备忘录一级页 + 配对 token | 断网续传、去重、删除同步 |
