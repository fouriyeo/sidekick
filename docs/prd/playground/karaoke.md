# K歌 / 人声扩音（候选）

> 这篇回答：这个想法能不能做、哪种形态最可行、如果做 P0 长什么样、怎么验证。
> 不包含：实现代码与具体 API（转 engineering 后再写）、排期承诺。**状态：研究完成，未开发、未排期。**

## 1. 需求原话

> 「手机播放音乐，连一副耳机，我唱歌的时候人声从手机喇叭播放出来；担心无限正反馈；不想买 K 歌设备。」

拆成两个 job：

- **自听**：听到自己被放大（耳返）。
- **外放**：让房间/别人听到（扩音）。
- 房间是否也要听到伴奏？——这决定形态，也决定「耳机该放什么」。

## 2. 形态与可行性

| 形态 | 做法 | 结论 |
| --- | --- | --- |
| A 私密伴奏 + 人声外放 | 他 App 音乐走耳机，Sidekick 人声走喇叭 | ⚠️ 双输出路由，机型相关；最难 |
| B 伴奏 + 人声都外放 | 音乐 App 外放 + 手机麦混入人声 | ⚠️ 有线耳机插着时媒体回不到喇叭；蓝牙麦 SCO 不稳 |
| C 耳返 | 人声和伴奏都走耳机 | ✅ 最简单；免费 K 歌 App 已有，差异化弱 |
| D 电脑/电视伴奏 + 手机无线麦 | 电脑放歌，手机只负责人声外放 | ✅ 最稳，符合「手机是外设」 |
| E 蓝牙音响 + 手机麦 | 音乐 + 人声都走蓝牙音响 | ✅ **推荐先验证**：单输出、绕开双路由/SCO；短板是 A2DP 延迟 |
| F App 自播伴奏 | 内置曲库/播放器 | ❌ 版权/曲库/混音，P2 |

结论：**E 最适合先验证**；A 是原始想法但最不确定；D 最稳；C 已有替代。

## 3. 技术要点

### 3.1 现有链路不能直接用

- 采集是 WebView `getUserMedia` + `ScriptProcessor(2048)`，16k 下 **128ms/块**，AEC/NS/AGC 全开（见 [audio-pipeline.md](../../engineering/audio-pipeline.md)）。
- WebView 不能可靠指定输出设备（`AudioContext.setSinkId` 要 Chrome 110+，项目基线 WebView 103）；Android 上 getUserMedia 约束也不可控。
- 仓库没有原生音频代码；要做实时链路，需新增 Kotlin Tauri 插件（或 Rust oboe）。

### 3.2 E 的链路

- `AudioRecord`（内置麦，48k，按需关 AGC/NS）→ 限幅/增益/啸叫检测 → `AudioTrack`（`USAGE_MEDIA`）→ 系统混音 → A2DP → 蓝牙音响。
- 音乐 App 继续走自己的媒体流；两条流在系统混音器混合；**不申请音频焦点**，音乐不被暂停。
- 不用 `VOICE_COMMUNICATION`、不进 `MODE_IN_COMMUNICATION`，避免 SCO 抢占 A2DP。
- 不录音、不落盘、不联网；前台可见指示。

### 3.3 延迟

| 段 | 估算 |
| --- | --- |
| 内置麦 + 应用环路 | 20–60ms |
| A2DP | 150–300ms |
| 合计（E） | 170–360ms |

自听 p95 ≤50ms 才自然；E 的 A2DP 是主要短板。缓解：AUX 线 / 低延迟模式音箱 / 接受轻微回声。A 形态用有线耳机可到 30–90ms，但路由最难。

### 3.4 啸叫

- 闭环增益 > 1 必啸叫；**不能承诺零啸叫**。
- 限幅（约 -3dBFS）、增益上限（默认 +6dB / 上限 +12dB）、啸叫检测（FFT/陷波）自动回落、一键静音。
- E 的音箱离麦远，余量大；A/B 的手机喇叭离麦近，余量小。
- 媒体模式下硬件 AEC 基本不可用；软件 AEC 列 P1。

### 3.5 路由

- A/B 依赖 `setCommunicationDevice` / `setPreferredDevice`；有线耳机 + 喇叭可能共用输出线程；输入可能被平台配对回内置麦；蓝牙麦 SCO 抢占 A2DP。
- E 不需要这些 API：媒体流自动走 A2DP。
- 系统级「分应用输出」（三星 Separate App Sound / 小米 Sound Assistant）可零代码实现 A，但非通用。

## 4. 如果做 P0（E 形态）

1. 一键启停（前台页面），状态「扩音中 · 不录音」。
2. 应用内增益滑杆 + 硬上限；输入/输出电平。
3. 限幅 + 啸叫检测自动回落 + 一键静音；**音量只自动降，不自动升**。
4. 路由/连接提示：未连蓝牙音响时提示；蓝牙断开即停。
5. 前台 only；后台/锁屏/来电/断开 100ms 内停；会话上限 60 分钟。
6. 与 ASR 麦克风、备忘录录音互斥。
7. 专属隐私说明；不新增权限（`RECORD_AUDIO` / `MODIFY_AUDIO_SETTINGS` 已有）。

不做什么：录音回放、歌词、直播、伴奏自播、双输出硬做、后台 FGS。

## 5. 验证（Gate 0）

用现成「扩音器 / Mic to Speaker」App + 目标手机/蓝牙音响，先花 30 分钟：

1. 音乐 + 人声是否同时从音响出；
2. 延迟/回声能否接受；
3. 音乐串入人声是否明显；
4. 10 分钟是否断连/过热；
5. 音量平衡是否可用。

通过线：owner 自己愿意连续用 3 次；5 人试用 ≥3 人愿意再用；无啸叫失控；延迟/串音在可接受范围。
不过：换 AUX 有线音箱 / 形态 D / 停。

## 6. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| A2DP 延迟/回声 | 唱得别扭 | AUX 线、低延迟音箱、接受轻微回声 |
| 音乐串入人声 | 「双重伴奏」 | 音箱远离手机、麦克风靠近嘴、噪声门 |
| 音量共用 | 人声/音乐比例难调 | 应用内增益 + 手动平衡 |
| 蓝牙音箱差异 | 延迟/音量/断连 | 试用清单 + 兼容说明 |
| 手机麦质量 | 人声闷/小 | 48k、HPF、增益；必要时外接麦（P1） |
| 发热/掉电 | 连续使用 | 60 分钟上限、实测 |

## 7. 隐私与权限

- 不录音、不落盘、不联网、不上传；音频只在内存与 A2DP 输出。
- 前台可见指示；停止/切后台/锁屏/来电/断开即停；结束释放 `AudioRecord`/`AudioTrack`。
- 复用 `RECORD_AUDIO` + `MODIFY_AUDIO_SETTINGS`；不申请 FGS/通知/MediaProjection。
- 与「外设麦克风」（按住说话 → 百炼转写）是两条链路，文案不复用「上传百炼」。
