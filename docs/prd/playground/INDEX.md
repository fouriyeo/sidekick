# 玩法 · 非主线小功能候选池

> 这篇回答：Sidekick 里那些「有趣但不属于主线」的小功能放在哪、怎么进、怎么退出。
> 它是**候选池 + 独立开关**，不是第二主功能，也不是功能大杂烩。当前只有方案：**未开发、未排期**。
> 决策：D131（模块存在，候选池制）；本页 `status: draft` 表示入口/Gate 仍可改，K歌条目未立项。

## 1. 定位

- 收纳 owner 想到的趣味小点子；每个条目是**独立小功能**，可单独开关/隐藏。
- 主功能（宠物、外设麦克风、备忘录、英语角、用量、AI 联动等）优先；玩法不抢 P0、不改主流程、不进北极星指标。
- 共享手机壳、设置、权限说明；不新增权限/后台/落盘，除非该条目单独立项。
- 工作名「玩法」（slug `playground`），正式名字在模块转正时再定。

## 2. 不是什么

- 不是第二个产品，也不是「什么都往里塞」的杂货铺。
- 不做社交、账号、排行榜、分享、打卡。
- 不承诺排期：候选池 ≠ roadmap；只有过 Gate 0 才写 PRD/排期。
- 不因为「有趣」牺牲隐私与主流程稳定性。

## 3. 入口与形态

| 项 | 规则 |
| --- | --- |
| 入口 | 建议：设置 › 玩法（列表），待评审；每个条目独立小页/卡片；**不占**宠物页顶栏第 6 个热区 |
| 开发期 | `?view=playground`（DEV）；正式入口等模块转正评审 |

| 回滚 | 条目可隐藏/下线，不影响主功能 |

## 5. 入选门槛（Gate 0）

1. 场景真实：owner 自己会用；5 人试用 ≥3 人愿意再用（owner 自用例外需写明）。
2. 单条目 spike ≤2 人天；做不到就先不做。
3. 不新增权限/后台/落盘/上传；要新增必须单独立项。
4. 独立入口/开关，可一键隐藏回滚。
5. 不违反产品原则（隐私 > 情绪 > 效率；不做社交/账号/排行榜）。
6. 不排期承诺；过 Gate 0 才写 PRD，过试用才考虑转正。

## 6. 生命周期

点子 → 候选池（一句话 + 场景）→ Gate 0（≤2 人天）→ 隐藏入口原型 → 5 人试用 → 转正 / 继续观察 / 归档。

- 不通过的不删，标「归档」并写原因；以后可以重启。
- 同一时间最多 1 个条目在「原型/试用」，避免摊子铺太大。

## 7. 当前结论（K歌）

- 形态 A（伴奏走耳机、人声走喇叭）最难：双输出路由机型相关，需真机验证。
- 形态 E（蓝牙音响 + 手机麦）最可行：单输出、绕开双路由与 SCO；短板是 A2DP 延迟 150–300ms。
- 形态 D（电脑/电视放伴奏 + 手机当无线麦）最稳。
- 暂不开发；下一步是 owner 用现成扩音 App + 自己的蓝牙音响试听感（延迟/回声、音乐串音）。

## 8. 不做什么

- 不做第二主功能、大杂烩、社交/账号/排行榜。
- 不默认后台/常驻/录音/落盘/上传。
- 不把候选池当 roadmap，不承诺排期。
- 不因为「有趣」改主流程或挤占 P0。
