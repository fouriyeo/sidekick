# 本期范围

> 本期只做两件事：**情绪宠物** + **外设麦克风（AI 语音输入）**。
> 范围之外的想法写到“以后”，不要夹带进 P0。

## 1. 阶段划分

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| Phase 0 | 局域网 MVP、前端脚手架、产品规范、两份 PRD | ✅ 2026-10-31 |
| Phase 1 P0 | 情绪宠物 + 麦克风 AI 语音输入 + 横屏双姿态 + 本地持久化 + 设置 | 未开始 |
| Phase 1.1 P1 | 锁定说话/连续听写、喂零食、AI 状态映射、配对鉴权、release 打包 | 未开始 |
| Phase 2 P2 | 系统级虚拟麦克风、BLE、iOS、云同步、多语言 | 未开始 |

## 2. 平台矩阵

| 能力 | 手机（横屏） | 桌面（macOS） |
| --- | --- | --- |
| 情绪宠物 | ✅ 主体，全屏舞台 | ❌ 本期不渲染 |
| 麦克风采集 | ✅ 按住说话、波形、计时 | ❌ |
| 转写 | ❌ | ✅ 本机转写 |
| 文本输入 | ❌ | ✅ 当前焦点应用 / 剪贴板 |
| 状态反馈 | ✅ 倾听/转写中/完成/失败 | ✅ 不抢焦点的小浮窗 |
| 连接角色 | 客户端 | 服务端 + 本地客户端 |

**边界**：桌面和手机是两个独立产物，共享协议与基础组件，不共享页面布局。移动端只做横屏；不做跨端自适应。

## 3. P0 做什么

### 情绪宠物

- 首次见面、命名、默认名。
- 桌面陪伴：呼吸、眨眼、张望、伸懒腰、打哈欠、夜间睡觉。
- 触摸互动：摸摸、戳一戳；不做拖拽、不做复杂手势。
- 情绪与记忆：心情、精力、亲密度（隐藏数值）、离开后回来、跨重启保存。
- 横屏双姿态：支架模式、手持模式；自动 + 手动切换。
- 与麦克风联动：倾听、成功、取消、失败的情绪反应。
- 设置：名字、震动、声音、减少动效、姿态、屏幕常亮、重置、关于/隐私。

### 外设麦克风

- 从宠物界面一键进入；未连接时引导连接。
- 按住说话、上滑取消、最短/最长时长、后台停止。
- 手机录音权限、桌面辅助功能权限的说明与降级。
- 桌面本机转写；默认自动粘贴，失败/不安全时仅复制。
- 绝不自动按回车、绝不自动发送。
- 手机端状态反馈与最近一次转写卡片。
- 桌面端不抢焦点的小浮窗状态。

### 横屏双姿态

- 支架模式：宠物大、界面元素自动隐藏、底部居中麦克风胶囊、充电时保持常亮（可关）。
- 手持模式：宠物在上 2/3、右下大麦克风按钮、左下取消、界面元素常显。
- 姿态切换是状态变化，不是媒体查询；切换过程中不打断录音。

## 4. P1 / P2（先记录，不实现）

| 优先级 | 内容 | 为什么后置 |
| --- | --- | --- |
| P1 | 锁定说话 / 连续听写 | 需要 VAD、流式转写和更复杂的取消逻辑 |
| P1 | 喂零食、收藏、小游戏 | 容易变成任务系统，先验证纯陪伴是否成立 |
| P1 | AI 状态映射（working/waiting/error） | 先把宠物做成生命，再谈状态指示灯 |
| P1 | 配对与鉴权 | 当前仅可信局域网；上线前必须补 |
| P1 | release 签名与桌面打包 | 先验证体验，再处理分发 |
| P2 | 系统级虚拟麦克风 | 需要 macOS 虚拟声卡驱动，工程量大 |
| P2 | BLE 通道 | Tauri 移动端 BLE 生态弱，需自写插件 |
| P2 | iOS | 后台与音频限制需单独评估 |
| P2 | 云同步 / 云 ASR / 多语言 | 隐私与成本问题，需单独决策 |

## 5. 明确不做

- 手机端正式聊天主界面、消息历史、通知中心（现有调试聊天保留，不扩展）。
- 账号、云同步、社交、排行榜、好友。
- 宠物饥饿/死亡/掉级/签到/任务。
- 手机竖屏完整布局（只显示旋转提示）。
- 桌面端宠物渲染。
- 跨端响应式断点（`sm/md/lg` 一套通吃）。
- 系统级虚拟麦克风（P2）。
- 公共网络下的可用性承诺。

## 6. 跨功能契约

1. 宠物和麦克风共享手机横屏舞台，但代码分属 `mobile/features/pet` 与 `mobile/features/mic`。
2. 麦克风状态优先于宠物情绪：倾听时暂停随机 idle 行为，结束后恢复之前的心情。
3. 宠物永远不遮挡麦克风按钮、波形、计时和取消区域。
4. 宠物在麦克风失败时表达“关心”，不表达“责怪”；文案不出现“你怎么又没听清”。
5. 麦克风不依赖宠物渲染成功；即使 Rive 加载失败，录音与转写仍可用。

## 7. 发布标准（Phase 1）

- [ ] 两份 PRD 评审通过，ACCEPTANCE 全部 P0 用例通过。
- [ ] Realme 真机横屏 60fps；麦克风 p95 端到端 ≤ 3s（≤10 秒语音）。
- [ ] 录音全程可见；无后台录音；无原始音频落盘。
- [ ] 自动粘贴不按回车；目标窗口变化/密码框时只复制。
- [ ] 宠物跨重启保留名字与心情；重置有二次确认。
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm build` 通过。
- [ ] 文档树链接检查通过；`protocol/README.md` 与音频提案同步。

## 8. 范围变更规则

- 新增 P0 功能：必须说明它替代了哪个 P0，或给出明确排期；P0 模块总数不超过 5 个/功能。
- 任何“顺便做”的想法默认进 P1/P2，不直接进本期。
- 范围变化写入 [decisions.md](../decisions.md)，并同步两份 PRD 的版本号。
